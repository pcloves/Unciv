可玩的出生地与资源

第九课结束时，地图上已经有了完整的地形、山链和河流，但它还是一张“风景区”：没有文明、没有起点、没有资源。这一课跟生成流水线的最后一段——MapRegions 先把地图切成若干块肥沃度相近的区域，RegionStartFinder 给每块区域挑一个起点，StartNormalizer 再把不够玩的起点补齐，resourceplacement/ 的三个类最后把奢侈品、战略资源和奖励资源撒上去。读完你应当能解释：这些步骤服务的是开局公平与玩家的选择空间，而不是地图好不好看。

需要的基础：第七课的生成分支与 isMapEditor 判定，第八课的 Fertility 与温湿分布，第六、九课的地块分层与河流字段。源码版本：1df6249a41301056ddc4448a95a93ddf5403e061。

目标、回顾与场景

三个场景都来自新开一局的体验。场景一：同样的地图类型和大小，四家文明不会挤在同一片大陆，而是各占一块——这是第 1 节 MapRegions 按肥沃度分配与切分的结果。场景二：有的起点周围明显平坦，游戏却给它塞了几格丘陵、一两个绿洲或一份小麦——这是第 3 节 StartNormalizer 在做“保底”。场景三：同一张图上，有的文明周围是香料，有的是丝绸，城市扩张时总能发现新物产——这是第 4 节奢侈品“每个区域一种”的分配目标。无论哪种，判断标准都不是画面，而是这局游戏能不能正常开。

1. 区域：地图切成平衡的块

第七课的阶段链走到 assignContinents 之后是 RiverGenerator，再往下 MapGenerator 分了两条路：新游戏才做区域与资源，地图编辑器只做自然奇观加一个简单的 spreadResources 兜底（MapGenerator L204 isMapEditor 分支）。区域这块的工作全部在 mapregions/MapRegions.kt。入口按“地图什么样”分成两条路：

// MapRegions.generateRegions（部分代码）。问：N 个文明怎么瓜分一张图？
fun generateRegions(tileMap: TileMap, numRegions: Int) {
    if (numRegions <= 0) return                              // ① 编辑器：不做区域
    if (tileMap.continentSizes.isEmpty())
        throw Exception("No Continents on this map!")        // ① 数据没算好就直接报错

    // ② 一个覆盖全图的大矩形，按形状取半径
    val radius = if (tileMap.mapParameters.shape == MapShape.hexagonal
            || tileMap.mapParameters.shape == MapShape.flatEarth)
        tileMap.mapParameters.mapSize.radius.toFloat()
    else
        max(tileMap.mapParameters.mapSize.width / 2,
            tileMap.mapParameters.mapSize.height / 2).toFloat()
    val mapRect = Rectangle(-radius, -radius, radius * 2 + 1, radius * 2 + 1)

    // ③ 碎岛图：无视大陆，整图切矩形
    if (tileMap.usingArchipelagoRegions()) {
        val hugeRect = Region(tileMap, mapRect, -1)  // -1 = 忽略大陆数据
        hugeRect.affectedByWorldWrap = false         // 起点就放在接缝处
        hugeRect.updateTiles()
        divideRegion(hugeRect, numRegions)
        return
    }
    // ④ 大陆模式见下一段
}

② 矩形图与六边形/平面图的半径算法不同，这里不能混用。Region 内部一切“属于我吗”的判断都靠这个矩形和大陆 ID，所以矩形先是全图，之后会被逐层缩小。

③ 碎岛图（usingArchipelagoRegions 的定义是“最大大陆占全部陆地不到 25%”）没有值得按大陆分的主体，干脆把整图当一个区域切；continentID = -1 表示“不要按大陆过滤地块”，affectedByWorldWrap = false 表示“从接缝处开始量，别绕圈”。

④ 大陆模式的思路完全不同，它先统计每块大陆有多少 Fertility，再决定每块大陆放几个文明，最后逐块切分。

大陆模式分三步：统计肥沃度、按肥沃度分配文明、把每块大陆切成矩形。

// MapRegions.generateRegions 的大陆分支（部分代码）。问：文明怎么分到大陆？
val continents = tileMap.continentSizes.keys.toMutableList()
val civsAddedToContinent = HashMap<Int, Int>()   // 大陆 ID → 已分到几个文明
val continentFertility = HashMap<Int, Int>()     // 大陆 ID → 肥沃度总和
val continentToColumnsItsIn = HashMap<Int, HashSet<Int>>()  // 记列号，用来判断环绕

for (tile in tileMap.values) {                    // ① 一趟统计
    val continent = tile.getContinent()
    if (continent != -1) {
        continentFertility[continent] = tile.getTileFertility(true)
            + (continentFertility[continent] ?: 0)
        continentToColumnsItsIn[continent]!!.add(tile.getColumn())
    }
}

repeat(numRegions) {                              // ② 每分一个文明，重新挑最值的大陆
    val bestContinent = continents.maxByOrNull {
        continentFertility[it]!! / (1 + (civsAddedToContinent[it] ?: 0))
    }!!
    civsAddedToContinent[bestContinent] = (civsAddedToContinent[bestContinent] ?: 0) + 1
}

for (continent in civsAddedToContinent.keys) {    // ③ 用列号把大陆包成矩形
    val continentRegion = Region(tileMap, Rectangle(mapRect), continent)
    val cols = continentToColumnsItsIn[continent]!!
    continentRegion.rect.x = cols.filter { !cols.contains(it - 1) }.maxOf { it }.toFloat()
    continentRegion.rect.width = cols.size.toFloat()
    if (tileMap.mapParameters.worldWrap && cols.minOf { it } < continentRegion.rect.x)
        continentRegion.affectedByWorldWrap = true
    continentRegion.updateTiles()
    divideRegion(continentRegion, civsAddedToContinent[continent]!!)
}

① 每个地块的 Fertility 来自规则集：getTileFertility 先读地形（含特征）上 “Fertility for Map Generation” 一类 unique 的加总，再给临河 +1、临淡水 +1、checkCoasts = true 时临海 +2。临河与临淡水会同时命中，所以一条河正好 +2——源码注释特意点明这一点。同一趟顺带记录大陆出现在哪些列号上，用于第 ③ 步判断它是不是跨了地图接缝。

② 分配不是一次算好，而是 repeat(numRegions) 每轮重新比一次，候选值 = fertility / (1 + 该大陆已分到的文明数)。已分到 0 个时，候选值就是这块大陆的原肥沃度；某大陆分到过 1 个文明后，下一轮它参与比较的值变成 fertility / 2，再被分到一次则是 fertility / 3——分母按 1、2、3 递增，不是每次再砍一半。代入三块大陆 A=100、B=55、C=40：第一轮 100 / 55 / 40 选 A（A 计数 1）；第二轮 A 的值变成 100/2 = 50，输给 B=55，于是选 B；第三轮 A=50 大于 C=40 与 B=55/2=27.5，又选 A（A 计数 2）；第四轮 A=100/3≈33.3，最后归 C。所以“最肥的大陆连任”只在它仍比别人的当前值更高时发生：以 A 已被选一次为例，要压过还没被选的 B 需要 F_A/2 > F_B，即 F_A 超过两倍 F_B。这也解释了为什么“肥沃的大陆会分到更多文明，但不是全给它”。

③ 把大陆包成矩形时，先看列号集合里“哪几列是一段连续列的开头”——列号 c 入选的条件是 c−1 不属于本大陆；再取这些开头的列号最大者作为矩形左边界 rect.x，宽度取列号总数。它取的不是大陆的最大列号，所以不环绕时筛完只剩最左列，结果就是读者预期的那个左边界。代入两个例子：不环绕的大陆列号是 {−2,−1,0,1}，四列里只有 −2 的左边（−3）不在大陆中，筛完只剩 −2，于是 rect.x = −2、宽度 4，正好覆盖 {−2,−1,0,1}；最小列号等于 rect.x，不标记环绕。跨接缝的大陆换个更宽的例子：地图宽 10（列号 −5…4，环绕时相差 10 等价，5 ≡ −5），大陆占左边 3 列与右边 2 列，列号是 {−5,−4,−3,3,4}——它仍是一块连通的陆地，因为最右列 4 的右邻 5 折回来就是 −5。filter 找出的开头是 −5（−6 不在集合里）与 3（2 不在集合里），maxOf 取 3，于是 rect.x = 3、宽度 5，矩形向右铺 {3,4,5,6,7}：3、4 在地图内，5、6、7 越界，由 getTilesInRectangle 逐列换算坐标、再经 getIfTileExistsOrNull 的环绕补偿折回 −5、−4、−3（第六课讲过的补偿），五列正好覆盖整个大陆。这里取“最大开头”是必须的：若取 −5，矩形只能铺 −5…−1，落在接缝另一侧的 3、4 就被漏掉。此时最小列号 −5 小于 rect.x = 3，于是标记 affectedByWorldWrap。updateTiles 在环绕时用同一规则重算 rect.x，并把宽度改成“实际有地块的列数”；不环绕时宽度保持 maxColumn − minColumn + 1 并清掉标记。它同时只保留属于本大陆、落在矩形内的格子，把 getTileFertility(continentID != -1) 累加成 totalFertility。

// MapRegions.divideRegion 与 splitRegion（部分代码）。问：一块地怎么切成两份才公平？
private fun divideRegion(region: Region, numDivisions: Int) {
    if (numDivisions <= 1) { regions.add(region); return }   // ① 终止：收下这块

    val firstDivisions = numDivisions / 2                    // ② 整数除法向下取整
    val splitRegions = splitRegion(region, (100 * firstDivisions) / numDivisions)
    divideRegion(splitRegions.first, firstDivisions)         // ⑦ 两块各自再分
    divideRegion(splitRegions.second, numDivisions - firstDivisions)
}

切分的脑内模型是分蛋糕：要 4 份就先对半切一刀（二分），再把两半各自递归切到份数用完；每刀切在哪里由“肥沃度对齐”决定，而不是面积对齐。

① 递归的终止条件不是“分得够小”，而是“份数分完”。所以最终区域数恒等于调用方传进来的 numRegions——4 家大文明就正好 4 块区域，多一块少一块都不会出现。

② 先算前半部分的份数与百分比：4 分成 2+2（各 50%），3 分成 1+2（33%+67%）。整数除法向下取整，奇偶数都能处理。

③ 目标不是“面积相等”，而是“肥沃度按比例相等”：目标值 = totalFertility × firstPercent / 100。

④ 每刀沿当前这块的长边切（宽大于高切竖刀，否则切横刀），刀口只能是直线、位置只能逐格挪——这是矩形切分法的根源限制。方向每刀重选：极端细高的区域层层横切，出来是上下堆叠的横条；极端矮胖则是并排竖条；长宽接近的区域一刀之后往往换向，4 份大致呈 2×2 的田字格。代入 13×20 的区域：先横切成两块 13×10，每块宽 13 已大于高 10，于是改为竖切成 6 列与 7 列。切完框内仍只有本大陆的格子属于区域，所以区域的真身是“框内的大陆部分”，边缘常有海洋掏出的洞；刀口按肥沃度对齐目标，肥处切得窄、贫处切得宽，四块大小并不均等。

⑤ 试刀的方式是窄带累加：以高 ≥ 宽、切横刀为例，第 k 轮取的是 Rectangle(rect.x, rect.y + k − 1, rect.width, 1f)——一条“整块宽 × 1 行高”的横带，y 从区域底边起每轮 +1；宽大于高时对称地取“1 列宽 × 整块高”的竖带，x 每轮 +1。跟踪调试时看到的 [−6,−7,13,1] → [−6,−6,13,1] → [−6,−5,13,1] 读法是：x=−6、宽 13 不变（整块区域的），y 从 −7 起每轮 +1、高固定 1——即同一块区域（底边 y=−7、宽 13）最底下的第 1、2、3 行。窄带只用来累加，不动任何矩形；循环全部走完才按 bestSplitPoint 一次性切割：切下的一块取底部（或左侧）bestSplitPoint 行（列），剩下的一块 y（或 x）上移、高度（宽度）减去该数，随后两块各自 updateTiles()。

⑥ 窄带里只把属于本大陆的格子计入 Fertility，其他格子（海洋或别的大陆）加 0，但仍占着位置；碎岛模式（continentID == -1）不做大陆过滤，带里所有格子直接计入。

⑦ 切完两块各自递归，直到份数用完。区域内部用 updateTiles 重算地块与 totalFertility——这也是前面所有矩形操作最终“生效”的地方。

延伸：区域为什么“方方正正”，有没有更自然的方案

区域只是生成期的中间数据：它决定起点、城邦与资源往哪儿放，画完地图就丢弃，游戏里没有任何国界线式的可视化，玩家看到的“区域”只有间接效果（比如两个文明的奢侈品种类明显不同）。所以切分方正一点，玩家根本感知不到，也就不值得为“好看”多花成本。真想要更自然的边界，经典做法是 Voronoi：给 n 个种子点，每个格子划给最近的种子，边界天然曲折；再按“交换边界格后肥沃度更均衡”迭代几轮（类似 k-means），公平性也不丢。这和背包问题不像：背包问题是在“选哪些物品”的组合空间里找最优（NP 难），而这里每刀的候选位置只有十几个，直接枚举取最接近目标的一刀，是 O(宽+高) 的贪心逐刀，不涉及组合爆炸。想两者兼得（自然边界 + 肥沃度均衡），Voronoi + 均衡迭代正是教科书写法，代价是代码量与调试成本翻几倍——Unciv 选矩形二分，是“公平优先、观感无所谓”的典型取舍。

区域切好后，每个区域还要定一个“类型”，供资源与起点规则按区域筛选（比如“丘陵区域多出铁”）。类型来自规则集里地形挂的 region unique：

// MapRegions.assignRegionTypes（完整）。问：每块区域是什么“风土”？
private fun assignRegionTypes() {
    val regionTypes = ruleset.terrains.values
        .filter { getRegionPriority(it) != null }
        .sortedBy { getRegionPriority(it) }        // ① 优先级升序

    for (region in regions) {
        region.countTerrains()                     // ② 统计地形与 Coastal
        for (type in regionTypes) {
            // ③ 先判排除条件
            if (type.getMatchingUniques(UniqueType.RegionRequireFirstLessThanSecond)
                    .any { region.getTerrainAmount(it.params[0])
                        >= region.getTerrainAmount(it.params[1]) })
                continue
            // ④ 再判入选条件，命中即定型
            if (type.getMatchingUniques(UniqueType.RegionRequirePercentSingleType)
                    .any { region.getTerrainAmount(it.params[1])
                        >= (it.params[0].toInt() * region.tiles.size) / 100 }
                || type.getMatchingUniques(UniqueType.RegionRequirePercentTwoTypes)
                    .any { region.getTerrainAmount(it.params[1])
                        + region.getTerrainAmount(it.params[2])
                        >= (it.params[0].toInt() * region.tiles.size) / 100 }) {
                region.type = type.name
                break
            }
        }
    }

所有“放多少、放哪格”最终都汇到这两个函数。脑内模型是两趟采购：第一趟只在“干净”（无 impact 气味）的格子里放；没放够，第二趟退而求其次，每次挑气味最淡的格子补齐。

③ 一格能长多种资源时（例如同一片草原能出小麦也能出马），按 “Generated with weight” 的权重随机——这是资源之间数量比例的控制点。
