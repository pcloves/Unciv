山地与河流

第八课讲完陆海和气候，地图上已经有了草原、荒漠和冻土，但还没有一座山、一条河。这一课跟两条生成线：MapElevationGenerator 先用一块噪声给陆地“拔高”，再用细胞自动机把散点揉成山脉和丘陵带；RiverGenerator 则在格子与格子的边上“画”河流，从内陆源头一路走到海。读完你应当能区分 Unciv 里“格子属性”和“边属性”两套语义，并解释生成器对山地和河流各自加了什么约束与修正。

需要的基础：第六课的河流三布尔边存储与邻居查询，第八课的柏林噪声与温湿字段。源码版本：1df6249a41301056ddc4448a95a93ddf5403e061。

目标、回顾与场景

三个场景都来自游戏里看得见的地方。场景一：同一张图上，山地总是连成一条条链，丘陵围着山转，而不是满图撒胡椒面——这是本课第 2 节细胞自动机的产物。场景二：把新游戏高级设置里的 Map Elevation 滑块（0.6～0.8）拉高，山地和丘陵明显变多——这是第 1 节幂函数的参数。场景三：荒漠里挨着河的格子会变成泛滥平原（Flood plains），游戏内“把这块地变成 River”的文明能力（如俄罗斯的领土扩张、某些伟人）也能凭空画出一条新河——前者靠生成结束后的 convertTerrains，后者靠运行时的 continueRiverOn，两条路径都收在本课。

本课的三个问题

  • 山地丘陵：噪声阈值怎样分出平地/丘陵/山？为什么还需要修形？
  • 边的语义：河流为什么存在边上而不是格子里？三个布尔怎样覆盖六条边？
  • 走线与约束：一条河怎样从源头走到海？哪些约束防止它画出不像河的东西？

读完还要会一件事：不看正文，对“地图上某条河是怎么来的、改哪个参数山会变多”这类问题，说出证据在源码的哪一段。

口述上一课的三个结论

  1. 第八课：山地（OccursInChains）在温湿阶段为什么被整组跳过？（提示：elevationTerrains）
  2. 第六课：A 查它与右上方 B 之间的河、B 查与 A 之间的河，读的是哪个字段？
  3. 第八课：Boreal 类型的湖层为什么把 scale 锁死 5.0？（提示：湖是河流的源头）

这三条是本课的直接地基。答不上来的先回 第八课第 5 节、第六课河流段扫一眼。

1. 山地丘陵：噪声定种子

第七课的阶段链里，第 3 步是 raiseMountainsAndHills。它属于 MapElevationGenerator——注意这个类名里的 Elevation（海拔）与第八课陆海阶段的 elevation 噪声不是同一个东西：陆海阶段的 elevation 决定水陆，算完就丢；这里的“海拔”只作用于已经生成的陆地格，决定它是平地、丘陵还是山。入口前半段：

// MapElevationGenerator.kt 的构造与三个候选表；①～④ 与右侧对应。
internal class MapElevationGenerator(
    private val tileMap: TileMap,
    private val ruleset: Ruleset,
    terrains: List<MapGenerator.TerrainOccursRange>,
    private val randomness: MapGenerationRandomness
) {
    // ① 三个候选表：平地 / 丘陵 / 山地
    private val flats = terrains.filter {
        !it.terrain.impassable && it.terrain.type == TerrainType.Land
        && !it.rareFeature && !it.isRough }
    private val hills = terrains.filter {
        (it.terrain.type == TerrainType.Land
            || it.terrain.type == TerrainType.TerrainFeature)
        && it.occursInGroups && !it.rareFeature }
    private val mountains = terrains.filter {
        (it.terrain.type == TerrainType.Land
            || it.terrain.type == TerrainType.TerrainFeature)
        && it.occursInChains && !it.rareFeature }
}

① terrains 参数是第八课见过的 TerrainOccursRange 列表（MapGenerator 的 terrainConditions）。三个私有表按 unique 分桶：flats 是“非不可通行、非崎岖”的平地（草原、平原……）；hills 是带 Occurs in groups around high elevations 的地形；mountains 是带 Occurs in chains at high elevations 的地形。

两个 unique 的原文和界面名都对上了：原版规则集里 Hill 是 TerrainFeature、带 “Occurs in groups…”，Mountain 是 Land、带 “Occurs in chains…”（Terrains.json L171 与 L136，Kotlin 侧 Terrain.isHill/isMountain 也是按这两个 unique 判定的）。所以 buckets 不写死 “Hill”/“Mountain” 名字——模组可以自带别的山丘地形，只要挂对应 unique。

注意 hills/mountains 的过滤条件允许 Land 或 TerrainFeature：山可以是基础地形（原版 Mountain），丘陵可以是特征（原版 Hill，画在草原/平原等基础地形之上）。这个差别在 applyTerrain 里还会用到。

主函数先给每个陆地格算一个噪声海拔，过一条幂曲线再切三段：

// MapElevationGenerator.raiseMountainsAndHills（部分代码）；①～⑥ 与右侧对应。
fun raiseMountainsAndHills() {
    if (flats.isEmpty()) return   // 纯陆地模组兜底

    // ① 抽本阶段的 z 层（噪声种子）
    val elevationSeed = randomness.RNG.nextInt().toDouble()

    // ② 地图类型偏移：boreal 更多山
    val mapSpecificElevationOffset = when (tileMap.mapParameters.type) {
        MapType.boreal -> +0.03
        else -> 0.0
    }
    // ③ 幂指数：滑块越大指数越小
    val exponent = 1.0 - tileMap.mapParameters.elevationExponent.toDouble()
        - mapSpecificElevationOffset
    fun Double.powSigned(exponent: Double) =
        abs(this).pow(exponent) * sign(this)

    tileMap.setTransients(ruleset)

    for (tile in tileMap.values) {
        if (tile.isWater) continue
        // ④ 每格：小尺度噪声 → 保号幂
        val elevation = randomness.getPerlinNoise(
            tile, elevationSeed, scale = 2.0).powSigned(exponent)
        // ⑤ 三段阈值：>0.7 山 / >0.5 丘陵 / 否则平地
        if (elevation > 0.7 && mountains.isNotEmpty())
            applyTerrain(tile, mountains)
        else if (elevation > 0.5 && hills.isNotEmpty())
            applyTerrain(tile, hills)
        else
            applyTerrain(tile, flats)
    }

    // ⑥ 修形（第 2 节）+ 全图刷新缓存
    cellularMountainRanges()
    cellularHills()
    for (tile in tileMap.values) tile.setTerrainTransients()
}

① 与第八课各阶段同款：从 RNG 抽一个整数切 z 层，循环体内不再动 RNG。

② 只有 boreal（北方冻土）加 0.03 偏移——偏移从指数里扣，山更多（下一段代入计算）。

③ elevationExponent 就在新游戏高级设置的 Map Elevation 滑块（MapParametersTable L484，范围 0.6～0.8，默认 0.7）。指数 = 1 − 滑块值：滑块越大，指数越小。

④ 噪声 scale 写死 2.0——比陆海阶段的默认 30 小得多。scale 是“多少格走完一个起伏周期”（第八课第 3 节），2 意味着海拔几乎每两三格就换一个值：这正是不希望山连片的“种子”分布，成链交给第 2 节的修形。

⑤ 为什么④算出的噪声不能直接当 elevation、中间要过一道 powSigned？两个原因。第一，量程对不上：噪声输出集中在 ±0.55 附近，而阈值写死 0.7/0.5——不过幂直接比，一座山都切不出来（0.55 > 0.7 永远为假）。第二，滑块要能调“山的多与少”。powSigned 是保号幂（先取绝对值做幂、再乘回正负号），指数 0.3 小于 1，对 0 到 1 之间的数是抬升：0.050.3 ≈ 0.41、0.30.3 ≈ 0.70、0.550.3 ≈ 0.84。抬升不是均匀的——越小的数被抬得越狠（0.05 抬了 8 倍，0.55 只抬了 1.5 倍），整体把“少数原本较高的格”推进阈值线内。指数正是滑块控制的旋钮：指数变小（滑块拉大），抬升更猛，更多格子过线成山。如果你来设计“滑块直接当阈值”的方案（滑块 0.8 就用 0.8 当线），量程问题无解——噪声最大才 0.55，阈值 0.6～0.8 段永远切不出任何山，滑块只在 0.5 以下才有效果，界面却得展示一个“看起来没用”的 0.6～0.8 区间。过一道幂，阈值不动、动的是值的分布，滑块全程有效。

⑥ 两个修形函数在下一节；结束后全图 setTerrainTransients 刷新 isMountain 一类缓存。

把“幂后阈值”换算回“幂前噪声值”更直观：幂后 > 0.7 等价于幂前 n > 0.71/0.3 ≈ 0.30。为什么指数是 1/0.3 而不是 0.3？因为这是反解：源码方向是“幂前 → 幂后”（n0.3 > 0.7），我们想知道“幂前多大才过线”，就要把 0.7 开 0.3 次方——幂和开方互为逆运算，n0.3 > 0.7 两边同时取 1/0.3 次幂（即开 0.3 次方）得 n > 0.71/0.3。1/0.3 ≈ 3.33 就是那个“为什么有个 1/3”的来历——1 除以指数 0.3，不是凭空出现的常数。不同滑块位置的换算（0.71/指数 与 0.51/指数，即山与丘陵的幂前门槛；数值越小越容易成山）：

Map Elevation 滑块指数 1−滑块−偏移山的幂前门槛丘陵的幂前门槛

// MapElevationGenerator.applyTerrain（完整）；①～④ 与右侧对应。
private fun applyTerrain(tile: Tile,
        terrains: List<MapGenerator.TerrainOccursRange>) {
    // ① 组内先按温湿过滤，全不匹配再整组随机
    val desiredTerrain = (terrains
        .filter { it.matchesTempAndTerrain(tile) }
        .ifEmpty { terrains }).random(randomness.RNG)

    // ② 先摘掉现有的山丘类特征
    tile.dropElevatedFeatures()

    if (desiredTerrain.terrain.type == TerrainType.Land) {
        // ③ Land：直接写基础地形名
        tile.baseTerrain = desiredTerrain.name
    } else {
        // ④ TerrainFeature：选一个能承载它的平地再叠特征
        val baseTerrains = flats.filter {
            desiredTerrain.terrain.occursOn.contains(it.name)
            && it.matchesHumidityAndTemp(tile) }
            .ifEmpty { flats.filter {
                desiredTerrain.terrain.occursOn.contains(it.name) } }
        if (baseTerrains.isEmpty()) return
        val baseTerrain = baseTerrains.random(randomness.RNG)
        tile.baseTerrain = baseTerrain.name
        tile.addTerrainFeature(desiredTerrain.name)
    }
}

2. 细胞自动机修形

阈值切出来的山地是噪声形状——原版 scale=2 的噪声切完，山是一小撮一小撮的孤立斑点。但玩家期待的“山脉”是连绵的链。MapElevationGenerator 用两轮细胞自动机（cellular automata）修形：每轮先扫描全图给格子挂临时标记，再统一兑现标记，循环 5 次。先看山地的版本：

// MapElevationGenerator.cellularMountainRanges（部分代码）；①～⑤ 与右侧对应。
private fun cellularMountainRanges() {
    if (mountains.isEmpty()) return

    // ① 目标：现有山数 × 2
    val targetMountains =
        tileMap.values.count { it.isMountainTerrain() } * 2
    val impassableTerrains = ruleset.terrains.values
        .filter { it.impassable }.map { it.name }.toSet()

    for (i in 1..5) {
        var totalMountains =
            tileMap.values.count { it.isMountainTerrain() } * 2

        for (tile in tileMap.values) {
            if (tile.isWater) continue
            // ② 数邻居：几个山、几个不可通行
            val isMountain = tile.isMountainTerrain()
            val adjacentMountains =
                tile.neighbors.count { it.isMountainTerrain() }
            val adjacentImpassible =
                tile.neighbors.count { it.baseTerrain in impassableTerrains }

            // ③ 四条标记规则
            if (adjacentMountains == 0) {
                if (isMountain && randomness.RNG.nextInt(until = 4) == 0)
                    tile.addTerrainFeature(lowering)   // 孤山：1/4 概率降
            } else if (adjacentMountains == 1) {
                if (!isMountain && randomness.RNG.nextInt(until = 10) == 0)
                    tile.addTerrainFeature(rising)     // 单邻山：1/10 概率升
            } else if (adjacentImpassible == 3) {
                if (isMountain && randomness.RNG.nextInt(until = 2) == 0)
                    tile.addTerrainFeature(lowering)   // 邻 3 不可通行：1/2 概率降
            } else if (isMountain && adjacentImpassible > 3) {
                tile.addTerrainFeature(lowering)       // 邻 >3：必降
            }
        }

        // ④ 统一兑现：rising 升山、lowering 降回平地
        for (tile in tileMap.values) {
            if (tile.isWater) continue
            if (tile.terrainFeatures.contains(rising)) {
                tile.removeTerrainFeature(rising)
                if (totalMountains >= targetMountains) continue
                totalMountains++
                applyTerrain(tile, mountains)
            }
            if (tile.terrainFeatures.contains(lowering)) {
                tile.removeTerrainFeature(lowering)
                if (totalMountains * 2 <= targetMountains) continue
                totalMountains--
                applyTerrain(tile, flats)
            }
        }
    }
}

① 目标数量 = 当前山数 × 2。山变密的主要推动力就是这个翻倍目标。

② 每格数两类邻居：adjacentMountains（含特征判定，isMountainTerrain 同时看 baseTerrain 和 terrainFeatures 里有没有 OccursInChains 的地形）和 adjacentImpassible（以基础地形是否不可通行计数，山本身不可通行，但这一计数也涵盖其他不可通行地形）。

③ 四条挂标记规则，语义是“链长什么样”：孤山（0 个山邻）倾向拆掉；贴着一个山的平地倾向长上去（链的延伸）；周围不可通行太多（3 个减半、超过 3 必降）倾向拆掉——这是防止大片不可通行地形堵死通路的约束，山链可以有，但不能把大陆切成不连通的几块。

④ 兑现有闸门：rising 只有在 totalMountains 还没到目标时才真升；lowering 只有在数量明显超目标（×2 还 ≤ 目标，即总数仍低于目标一半以上）才跳过降级——总效果是山数向“初始 × 2”靠拢。注意 ~Raising~/~Lowering~ 是带波浪号的假地形名，只活在内存里，兑现段第一件事就是摘掉它们，绝不会写进存档。

Godot 对照：把“修形”和“生成”分开

两段式结构（噪声定种子 → 细胞自动机修形）是可迁移的思路：噪声负责“哪里大概有山”，自动机负责“山的形状像山”。Godot 里你可以用 FastNoiseLite 出一张海拔图，再用相同两轮扫描的 GDScript/C# 修形——Godot 没有内置细胞自动机，但“挂标记→统一兑现→循环 N 次”本身就是十几行代码。分开的好处是调参时能独立看效果：scale 只影响种子分布，概率规则只影响链的形状。Godot 4.x 均适用。

4. 从源头到海：走顶点

RiverGenerator 的类注释开门见山：地图生成沿六边形的顶点（vertex）走，游戏内加河沿边操作——两条路径，本节先讲前者。入口先定“要画几条、从哪画”：

// RiverGenerator.spawnRivers（部分代码）；①～⑤ 与右侧对应。
fun spawnRivers(resultingTiles: MutableSet<Tile>? = null) {
    if (tileMap.values.none { it.isWater }) return   // ① 纯陆地图不画河
    // ② 河数 = 陆地格数 × 系数（默认 0.01，四舍五入）
    val numberOfRivers = (tileMap.values.count { it.isLand }
        * riverCountMultiplier).roundToInt()

    // ③ 源头候选：优先远离水的山
    var optionalTiles = tileMap.values.asSequence()
        .filter { it.getBaseTerrain().isMountain && it.isFarEnoughFromWater() }
        .toMutableList()
    if (optionalTiles.size < numberOfRivers)
        optionalTiles.addAll(tileMap.values
            .filter { it.isHill() && it.isFarEnoughFromWater() })
    if (optionalTiles.size < numberOfRivers)
        optionalTiles = tileMap.values
            .filter { it.isLand && it.isFarEnoughFromWater() }.toMutableList()

    // ④ 分散选点（第八课资源分布同款）
    val mapRadius = tileMap.mapParameters.mapSize.radius
    val riverStarts = randomness.chooseSpreadOutLocations(
        numberOfRivers, optionalTiles, mapRadius)
    // ⑤ 逐条画
    for (tile in riverStarts) spawnRiver(tile, resultingTiles)
}

// isFarEnoughFromWater：距离 1..minRiverLength-1 内无水（默认 5 → 查 1..4 环）

        if (getTilesAtDistance(distance).any { it.isWater }) return false

    return true

// 源码注释：建议先在纸上画几个六边形再看这段，超级有用！
class RiverCoordinate(
    private val tileMap: TileMap,
    private val position: HexCoord,
    private val bottomRightOrLeft: BottomRightOrLeft
) {
    enum class BottomRightOrLeft {
        BottomLeft,    // 该格 7 点钟方向的顶点
        BottomRight    // 该格 5 点钟方向的顶点
    }
    // ① 用"锚定格 + 5/7 点钟"定位一个顶点
    private val myTile = tileMap[position]
    private val myTopLeft = tileMap.getIfTileExistsOrNull(x + 1, y)
    private val myBottomLeft = tileMap.getIfTileExistsOrNull(x, y - 1)
    private val myTopRight = tileMap.getIfTileExistsOrNull(x, y + 1)
    private val myBottomRight = tileMap.getIfTileExistsOrNull(x - 1, y)
    private val myBottomCenter = tileMap.getIfTileExistsOrNull(x - 1, y - 1)

    // ② 相邻的三个顶点：左右的必然相邻
    fun getAdjacentPositions(): Sequence<RiverCoordinate> = sequence {
        if (bottomRightOrLeft == BottomLeft) {
            yield(RiverCoordinate(tileMap, position, BottomRight))  // 同格另一侧
            if (myTopLeft != null)
                yield(RiverCoordinate(tileMap, myTopLeft.position, BottomRight))
            if (myBottomLeft != null)
                yield(RiverCoordinate(tileMap, myBottomLeft.position, BottomRight))
        } else { /* BottomRight 的镜像，三个候选同理 */ }
    }

    // ③ 该顶点 touches 的三个格子
    fun getAdjacentTiles(): Sequence<Tile> = sequence {
        yield(myTile)
        myBottomCenter?.let { yield(it) }
        if (bottomRightOrLeft == BottomLeft) myBottomLeft?.let { yield(it) }
        else myBottomRight?.let { yield(it) }
    }
}

// RiverGenerator.spawnRiver（部分代码）；①～⑤ 与右侧对应。
fun spawnRiver(initialPosition: Tile, endPosition: Tile,
        resultingTiles: MutableSet<Tile>?) {
    // ① 起点：源头格的两个底角随机选一个
    var riverCoordinate = RiverCoordinate(tileMap,
        initialPosition.position,
        RiverCoordinate.BottomRightOrLeft.entries.random(randomness.RNG))

    repeat(maxRiverLength) {
        // ② 顶点若已 touches 水 → 到站，停
        if (riverCoordinate.getAdjacentTiles().any { it.isWater }) return

        val possibleCoordinates = riverCoordinate.getAdjacentPositions()
        if (possibleCoordinates.none()) return   // ③ 走到地图边界的死角

        // ④ 贪心：按"三格中最小距海距离"分组，取最小的一组随机挑
        val newCoordinate = possibleCoordinates
            .groupBy { newCoordinate ->
                newCoordinate.getAdjacentTiles()
                    .map { it.aerialDistanceTo(endPosition) }
                    .minOrNull()!! }
            .minByOrNull { it.key }!!
            .component2().random(randomness.RNG)

        // ⑤ 涂边 + 前进
        riverCoordinate.paintTo(newCoordinate, resultingTiles)
        riverCoordinate = newCoordinate
    }
    debug("River reached max length!")   // 兜底：666 步还没入海
}

③ 目标是特征（Desert→Flood plains）时多一道检查：特征不能凭空存在，只能叠在 occursOn 允许的基础地形上——规则集里 Flood plains 只 occursOn Desert（Terrains.json L281，Oasis 也一样）。是荒漠才叠，不是就 continue 跳过。检查用的是 tile.lastTerrain.name——lastTerrain 是“基础地形 + 特征”里最顶上那层（Tile.kt L969），特征叠特征时看最顶层允不允许。occursOn 是一道合法性门：防止出现“草原泛滥平原”这类任何规则都没定义过的组合，宁可不转，不转出非法状态。

④ 每格改完立即刷缓存。注意调用时机：整图生成时对所有格子跑一遍；编辑器单步画河时（generateSingleStep 的 Rivers 分支）只对 resultingTiles 跑——这就是 spawnRivers 留那个参数的原因。

游戏内“把这块地变成 River”的能力走另一条路：continueRiverOn 在边上直接延伸河流（类注释特意把两个函数放在一起方便对比）。它给当前格的每条边算优先级——连海加分（除非已经有入海口）、接通开放端加分、形成三叉 Y 形减分——取最高优先级的一组随机挑一条，最后 setConnectedByRiver(..., convertTerrains = true) 落笔。你不需要记住优先级表的每个数，需要记住的是：生成期画河走顶点贪心长链，运行期加河走边级评分挑一条，两条路径最终都写同一组三布尔、都会触发 convertTerrains。运行期的 RNG 换成了 GameContext 的 stateBasedRandom（第七课讲过的 gameId 混入源），与生成期的 randomness.RNG 分属两套随机边界。

最后把本课散见的约束与修正归成一张表。读法：第一列是谁加的约束（对象）；第二列是约束本身；第三列是“没有它会怎样”——即约束防住的坏结果；第四列是源码位置。按“形态约束”和“功能约束”分两组，前者管像不像山和河，后者管地图还能不能玩。

取舍：为什么河存在边上而不是格子上

格子模型（“这块地是河”）实现最简单，但文明系列里河的语义是“跨过它有代价、沿它有收益”——移动减速和攻击减益作用于过边，淡水和加成作用于两侧格子。边存储精确表达这个语义，代价是三布尔的归属规则（下半圈归自己）和双向查询的间接性。另一个隐性收益：存档里每条边只出现一次，天然避免两侧格子各存一份可能矛盾的数据。做自己的游戏时，如果河流只需要“格子临河加成”、没有跨河战斗语义，格子模型反而更省事——先想清楚规则要用到边的哪些语义，再选存储。

心智模型

  • 山地丘陵两段式：scale=2 的小尺度噪声 + 保号幂定“种子”，两轮细胞自动机（挂标记→兑现，各 5 轮）把种子揉成链和群；Map Elevation 滑块改幂指数，指数越小山越多。
  • 修形有预算闸门：山向“初始 ×2”靠拢，丘陵在 90%～100% 之间微调；~Raising~ / ~Lowering~ 是只活在内存里的假地形名。
  • 河流是边属性：每格只存下半圈三布尔，上半圈查邻居；A 查 B 与 B 查 A 读同一个字段。
  • 生成画河走顶点：顶点 = 格子 + 5/7 点钟；每步三候选按“最小距海”分组贪心 + 组内随机 = 蜿蜒入海；数量 = 陆地 ×0.01，源头优先离水 ≥5 环的山。
  • 画完河的 convertTerrains 兑现 “Becomes X when adjacent to River”：荒漠→泛滥平原、冻土→草原、雪原→冻土；运行期加河走 continueRiverOn 的边级评分，另一套随机源。
  • 约束分两类：形态约束（山成链、河蜿蜒）管观感，功能约束（不可通行不连片、源头离水、数量预算）管可玩性。

练习 A · 推演滑块与修形（6 分钟）

三张相同 seed 的默认 perlin 图，分别只改一处：① Map Elevation 从 0.7 拉到 0.8；② 图类型换成 boreal（其他不动）；③ 假设把 cellularMountainRanges 的循环从 5 轮改成 1 轮。各自预测山地丘陵形态的变化，并说出源码依据。

展开核对要点

① 指数 0.3→0.2，山的幂前门槛从 ≈0.30 降到 ≈0.17（L46 与 L54 的代入），更多格子过 0.7 线成山；修形目标 = 初始 ×2，初始更多则目标也更高。② boreal 偏移 +0.03：指数 0.3→0.27，门槛 0.30→0.27，方向同①但幅度小；同时 boreal 湖多、离水候选少，河流源头更常从丘陵/陆地级出（spawnRivers 三级降级）。③ 1 轮时链端规则只延伸一次、孤山只拆一次：噪声切出的孤立斑点来不及连成链，山更接近阈值原始形态—— pepper 面而不是山脉。

练习 B · 手推一条河的前几步（8 分钟）

在纸上画 3×3 六边形（平顶），中间格是源头山格，右下方是海。按 spawnRiver 的规则推演：① 起点顶点在哪两个里选？② 若选了 7 点钟顶点，写出它的三个相邻顶点（用"锚定格 + 5/7 点钟"表示）；③ 到哪一步循环会 return？最后用 paintTo 的分支判断说明第二步涂的是谁的哪条边。

展开核对要点

① 源头格的 5 点钟或 7 点钟顶点（BottomRightOrLeft.entries.random）。② 7 点钟顶点的相邻顶点：同格 5 点钟、左上格（x+1,y）的 5 点钟、左下格（x,y−1）的 5 点钟——rights 只挨 lefts。③ 当顶点 touches 的三格中任一是水时 return（getAdjacentTiles().any { it.isWater }）；走地图边界死角（候选全 null）也会 return。涂边：同格换侧涂锚定格正下边；移向"共同 touches 格"涂自己的左下/右下边；移向下方新格则让新坐标涂它锚定格的对应下边——落笔永远写归属格自己的三布尔。

练习 C · 比较两条加河路径（5 分钟）

地图生成期的 spawnRiver 与游戏内的 continueRiverOn 都能画出一条河。从"坐标系、选择策略、随机源、落笔方式"四个方面各给一句对比，并说出它们最终汇合在哪两个点上。

展开核对要点

坐标系：顶点（格子+5/7 点钟）对边（六方向邻居）。策略：三候选按最小距海分组贪心+组内随机，对六邻边按连海/接通开放端/Y 形减分的优先级评分取最高组随机。随机源：生成期 randomness.RNG（种子属地图 seed 链），运行期 GameContext.stateBasedRandom（混入 gameId，第七课边界）。落笔：paintTo 的三个 paint 函数直接置布尔，对 setConnectedByRiver(..., convertTerrains = true) 统一入口。汇合点：都写同一组三布尔字段；都（直接或可选）触发 convertTerrains 的河岸转换。

练习 D · 本地核验（可选，5～10 分钟）

跑 :tests:test --tests "com.unciv.logic.map.MapGenerationTests"。terrainTileCountsReasonableFor* 的断言里有 Mountain ≈ 212（六边 Small）和 Hill ≈ 1804。想想这两个数字钉住的是第 1 节（阈值切分）还是第 2 节（修形）？为什么断言用两倍容差而 flatEarth 的 Mountain 容差放宽到 4 倍（源码注释说山地数量“WIDLY unstable”）？

展开核对要点

两个数字都同时跨两节：阈值切分给初值，修形把山拉向 ×2 目标、丘陵在 ±10% 内微调——断言钉住的是两节叠加后的总量。不稳定来源：修形每轮用 RNG 决定挂标记概率（nextInt(until=4) 等），且 applyTerrain 组内 random 也动 RNG，种子相同的图统计上仍波动；flatEarth 的纬度分布让陆地块更碎，阈值初值方差更大，所以 4 倍容差。（本课程核对时 Gradle MCP 实测 4 过 0 失败。）
