第二阶段 / 地图专题 · 地图专题收官

地图怎样被看见

地图专题的最后一课。前七课地图被生成（07～10）、被行走（11），但一直假设“玩家看得见全图”。真实游戏里你只看得见自己单位周围的一圈，走过的地方留下灰暗的记忆，没去过的地方一片黑。这一课回答三个问题：一格单位能看多远、视线怎么被山和森林挡住？文明的“可见集合”谁在什么时候重算？画面上的迷雾、探索过、没去过三种格子分别是哪层代码画的？这也是第二课埋的钩子的兑现——当时说 viewableTiles“谁在什么时候重算它，第 12 课讲地图显示时再追”。

需要的基础：第二课的 GameView/TileView 视角过滤（本课直接续上）；第六课的地形分层与 allTerrains；第十一课的 moveToTile 逐格落位（第 5 节的追踪起点）。源码版本：1df6249a41301056ddc4448a95a93ddf5403e061。

目标、回顾与场景

三个场景都来自玩一局的体验。场景一：侦察兵站在丘陵上，能看见山后面那格的森林，却看不见山脚下紧挨着的平地——视线不是“半径几格的圆”，而是要翻越高度。这是第 1 节的视线算法。场景二：你的单位走远了，刚才那片地变暗，但地图上还留着农场和边界的“旧照片”；等单位走回来，才发现农场早被敌人拆了。这是第 2、3 节的可见集合与 lastSeenImprovement。场景三：同一张地图，几千个格子每格十来种贴图，放大缩小、点选高亮同时发生——这些画面元素怎么组织才不卡。这是第 4 节的 TileGroup 分层。

本课的三个问题

  • 视线：getViewableTiles 按环推进时，“已见最高地形”怎么传递？山、丘陵、森林各是几层？
  • 账本：civ.viewableTiles 由哪几路来源拼成？单位移动、回合开始、读档分别在哪一步重算？
  • 画面：“看不见”（雾）、“探索过”（旧照片）、“没去过”（黑）三态分别由哪个查询和哪层图决定？

读完还要会一件事：不看正文，对一个单位从 A 走到 B，说出哪些格子的画面会变、各变什么，并指出每一处调用的方法名。

1. 一格能看多远：视线算法

视野的原子问题：站在 position、视野 sightDistance 的单位，能看见哪些格？入口是 TileMap.getViewableTiles（按 HexCoord 查）与它的包装 Tile.getViewableTilesList。它不是简单取“距离 ≤ sight 的所有格”——那就不需要这一节了。真实算法按环推进，每一格是否可见取决于来路上已见过的最高地形：

// TileMap.getViewableTiles（部分代码）。问：站在 (0,0) 视野 2，哪些格看得见？
val aUnitHeight = get(position).unitHeight          // ① 站的地方有多高
val viewableTiles = mutableListOf(ViewableTile(
    get(position), aUnitHeight,
    isVisible = true, isAttackable = false))         // ② 脚下永远可见

for (i in 1..sightDistance+1) {                     // ③ 逐环处理，多算一环
    val tilesToAddInDistanceI = ArrayList<ViewableTile>()

    forEachTileAtDistance(position, i) { cTile ->
        val cTileHeight = cTile.tileHeight           // ④ 这格本身多高

        // 第 sight+1 环只有比脚下高的才可见（forAttack 除外）
        if (i == sightDistance + 1 &&
            (cTileHeight <= aUnitHeight || forAttack))
            return@forEachTileAtDistance             // ⑤ 界外一环：只留高个

        val bMinimumHighestSeenTerrainSoFar = viewableTiles
            .filter { it.tile.aerialDistanceTo(cTile) == 1 }
            .minOf { it.maxHeightSeenToTile }        // ⑥ 邻居里最低的“已见最高”

        tilesToAddInDistanceI.add(ViewableTile(
            cTile,
            max(cTileHeight, bMinimumHighestSeenTerrainSoFar),     // ⑦ 传递：取大
            aUnitHeight >= bMinimumHighestSeenTerrainSoFar
                || cTileHeight > bMinimumHighestSeenTerrainSoFar,  // ⑧ 能看见它吗
            aUnitHeight >= bMinimumHighestSeenTerrainSoFar
                || cTile.unitHeight > bMinimumHighestSeenTerrainSoFar)) // ⑨ 能打它吗
    }
    viewableTiles.addAll(tilesToAddInDistanceI)      // ⑩ 本环算完才入账
}
return viewableTiles.filter { it.isVisible }.map { it.tile }

脑内模型是站在山顶环顾四野：视线一圈圈往外走，每格手里拿两样东西——自己的身高，和“到我这格为止、来路上见过的最高障碍”这个门槛。轮到某一格判定：把它内圈邻居的门槛都摆出来，取最低的那条当标尺——只要有一条门槛够低，它就看得见。它再把 max（自己身高，这条最低门槛） 作为自己的新门槛，传给从它向外去的邻格——门槛像接力棒一圈圈往外传，一格比一格更“知道路上有多高”。遮挡根本不需要射线检测：被挡住的，是那些所有内圈入口都领到了高门槛、自己又不够高的格子。影子是门槛传着传着自己显现的，形状由六边形几何决定——轴线上的格只有 1 个内圈入口，正后方那格的全部来路都经过同一个高格，单个高格就能投出一条笔直的窄影（REPL 实测：(1,0) 一格森林恰好只挡掉正后方的 (2,0)，19→18）；斜角位置的格有 2 个内圈入口，单个高格喂不满两条来路，几乎挡不住身后的格，得成排的高地才封出一片盲区。

① unitHeight 是“站上去的高度”：平地 0、丘陵 1、山 2，由 VisibilityElevation unique 决定（原版只有 Mountain [+2] 和 Hill [+1]）。

② 起点格无条件可见，初始的“已见最高”就是脚下高度——所以站在山上（a=2）时，一环的丘陵（b=1）挡不住任何东西。

③ 循环到 sightDistance+1：多算一环界外的格子，这是“站在平地也能看见远处的山”的来源（下一行就过滤）。

④ tileHeight 与 unitHeight 的差别在“挡不挡同高视线”：带 BlocksLineOfSightAtSameElevation 的地形（原版 Forest、Jungle）tileHeight = unitHeight + 1——森林自身 0 高，但挡平地单位的视线；山和丘陵不带这条，所以丘陵挡不住丘陵上的单位。

⑤ 第 sight+1 环只保留“比脚下高”的格：视野 2 的平地单位能看见 3 格外的丘陵和山，但看不见 3 格外的平地。REPL 实测：全平地图视野 2 见 19 格；把 (3,0) 改成丘陵，恰好变 20 格。

⑥ 关键一步：对候选格取一环内邻居（aerialDistanceTo == 1，即上一层已入账的格），从中挑 maxHeightSeenToTile 最小的——“最低的垭口决定能不能看见”。源码注释用 a（脚下）、b（路上最高）、c（目标）三个高度概括了全部场景：a≥b 时 b 不挡（平地看平地、丘陵连丘陵）；a<b 时要么 c>b（山冒出森林），要么看不见。

⑦ 每格记录自己的 maxHeightSeenToTile = max(自身高度, 来路最高)——传给下一环。这就是“高度沿视线传递”的实现。

⑧ 可见判定：a≥b（我比垭口高）或 c>b（目标比垭口高，注意是 tileHeight）。REPL 实测：平地单位隔着一格森林看不见二环的平地和丘陵（19−1=18 格），但看得见二环的山（c=2>b=1）。

⑨ 可打判定的尺子换成 unitHeight——“看得见”按 tileHeight、“打得着”按 unitHeight。丘陵+森林隔着丘陵位置时，tileHeight 那关过了，但 unitHeight 的 1 仍不大于垭口的 1，所以只能看不能打——测试 canSeeButNotAttackHillForestOverHill 钉死了这对判定的差别。远程攻击走 getViewableTiles(position, sight, forAttack = true)，界外一环也不放宽。

⑩ 本环全部算完才 addAll——同一环的格子不能互相“借道”：取邻居只从“已入账的更内圈”拿，循环开头那个攒本环结果的 ArrayList 就是干这个的（源码注释原话：“so we don't use tiles in the same distance to see over”）。

高度从哪来：unitHeight/tileHeight 不是独立字段，而是 setTerrainFeatures 时按地形 unique 算出的 @Transient 缓存：

    .sumOf { it.params[0].toInt() }                  // ① 各层高度相加
tileHeight = if (terrainHasUnique(UniqueType.BlocksLineOfSightAtSameElevation))
    unitHeight + 1                                  // ② 挡同高：再垫一层
else unitHeight

脑内模型是体检单打分：把格子叠的每种地形各查一遍“加几分、挡不挡人”，加总得身高。

① allTerrains 是第六课讲过的分层序列（基础地形 + 自然奇观 + 特征），每层带 VisibilityElevation 的都累加——原版只有 Mountain +2、Hill +1，所以丘陵+森林是 1（Forest 不加高度）。与移动代价查 lastTerrain 不同，这里逐层累加而非取最顶层。

② Forest/Jungle 带 "Blocks line-of-sight from tiles at same elevation"，tileHeight 比 unitHeight 多 1——效果是“挡住同高单位的视线”但“不挡更高单位的”。REPL 实测：丘陵+森林 unitHeight=1、tileHeight=2；平地+森林 unitHeight=0、tileHeight=1。

这一节的所有行为都有测试钉着：VisibilityTests（本地测试文件）用 18 条用例枚举了高度组合——canSeeForestOverPlains、cannotSeePlainsOverForest、canSeeHillOverPlains、cannotSeeHillOverHill、canSeeMountainOverHill、cannotSeeMountainOverHillForest、canSeeElevation3Tiles、cannotSeeHiddenElevation3Tiles、canSeeButNotAttackHillForestOverHill……本课核对重跑 18 过 0 跳过 0 失败。

Godot 对照：可见性是数据问题，不是渲染问题

直觉上“迷雾”像渲染效果（贴一层黑色遮罩），但这一节展示它是逻辑层的查询结果：getViewableTiles 纯读地形数据，输出一个集合，渲染只是消费它。Godot 里做战争迷雾同样建议先写“visibleTiles(civ) → Set<Vector2i>”的纯函数（用 Tokenized 高度数组 + 与本课相同的按环 DP），再让 TileMapLayer 按 set 差值刷贴图。Unciv 的“⑥ 取邻居最低垭口”是经典 symmetric shadowcasting 的简化版：六边形格数少，逐环遍历够快，不需要扇区裁剪那套复杂度。视差遮罩（森林挡半格）这类表现增强可以后加，只要数据层先对。

2. 文明的视野账本：updateViewableTiles

上一节的算法回答“一个单位看哪些格”。但游戏里问得更多的是“这个文明现在看得见哪些格”——它要汇总所有单位、所有城市、盟友和间谍。这份账本存在 Civilization.viewableTiles（@Transient 的 Set<Tile>，第二课见过它），由 CivInfoTransientCache.updateViewableTiles 统一重算。这个类名直译是“文明瞬态缓存”——放的就是这类“算起来贵、存着又不用进存档”的东西：

// CivInfoTransientCache.setNewViewableTiles（部分代码）。问：文明的可见集合怎么拼？
private fun setNewViewableTiles() {
    if (civInfo.hasSpectatorVision() || DebugUtils.VISIBLE_MAP) {
        civInfo.viewableTiles = civInfo.gameInfo.tileMap.values.toSet()   // ① 观战/调试：全图
        return
    }
    if (civInfo.isDefeated()) {
        civInfo.viewableTiles = emptySet()       // ② 已灭：什么都看不见
        return
    }

    val newViewableTiles = HashSet<Tile>(ourTilesAndNeighboringTiles)    // ③ 领土及邻格打底
    newViewableTiles.addAll(civInfo.units.getCivUnits()
        .flatMap { unit -> unit.viewableTiles.asSequence()
            .filter { it.getOwner() != civInfo } })                      // ④ 单位视野：去掉自家领土

    for (otherCiv in civInfo.getKnownCivs()) {
        if (otherCiv.allyCiv == civInfo || otherCiv == civInfo.allyCiv) {
            newViewableTiles.addAll(otherCiv.cities
                .asSequence().flatMap { it.getTiles() })                 // ⑤ 盟友城邦的领土
        }
    }

    newViewableTiles.addAll(civInfo.espionageManager.getTilesVisibleViaSpies())  // ⑥ 间谍：驻地一环

    civInfo.viewableTiles = newViewableTiles    // ⑦ 整表替换，防并发修改
}

脑内模型是公司的值班表：每个人（单位、城市、盟友、间谍）上报自己看得见什么，管理员不挑不拣全抄在一块白板上——谁走了擦掉重写，从不原地涂改。

① 观战者（spectator）与调试开关直接给全图。hasSpectatorVision 也覆盖“单人战败后转观战”的情况。

② 已灭文明置空——防止走进“前盟友的尸体领土”之类的幽灵视野（#9245）。

③ ourTilesAndNeighboringTiles 是另一个缓存（updateOurTiles 维护）：己方全部城市的格子加它们的邻居。领土本身永远“看得见”，所以账本先用它打底。单位在自家领土里挪动时，④ 的过滤让这次移动不触发整本重算（下一块讲）。

④ 每个单位带上自己第 1 节算好的视野，但滤掉“格主就是自己文明”的那部分——自家的地盘早就包含在上一步的打底里，没必要重复入账；而盟友领土上的自家单位视野照常入账（filter 只排除自己，不排除盟友）。

⑤ 已认识且互为宗主/盟友的城邦，其城市领土直接并入——联机的“共享视野”条款也走这条路。getKnownCivs 只含已认识的，没见过的文明不会白送视野。

⑥ 间谍驻扎的城市中心一环（EspionageManager.getTilesVisibleViaSpies，中心格 getTilesInDistance(1)）。

⑦ 算完整体替换引用而不是往旧集合里加——源码注释点名"to avoid concurrent modification problems"：别处正在迭代旧集合时，替换引用不会让它炸，原地改会。

账本算完不只有画面用。updateViewableTiles 的外层还做四件事，每一件都是“看见”在逻辑上的后果：

// updateViewableTiles 的后半段（部分代码）。问：看见之后，游戏还做了什么？
fun updateViewableTiles(explorerPosition: HexCoord? = null) {
    setNewViewableTiles()                            // ① 拼账本（上一块）

    updateViewableInvisibleTiles()                   // ② 谁能看见隐身单位
    updateLastSeenImprovements()                     // ③ 刷新改良的旧照片

    civInfo.viewableTiles.asSequence().forEach { tile ->
        tile.setExplored(civInfo, true, explorerPosition)
    }                                                // ④ 可见必已探索：记账

    val viewedCivs = HashMap<Civilization, Tile>()
    for (tile in civInfo.viewableTiles) {
        val tileOwner = tile.getOwner()
        if (tileOwner != null) viewedCivs[tileOwner] = tile
        val unitOwner = tile.getFirstUnit()?.civ
        if (unitOwner != null) viewedCivs[unitOwner] = tile
    }                                                // ⑤ 这次看见了谁家的地/单位

    if (!civInfo.isBarbarian) {
        for (entry in viewedCivs) {
            val metCiv = entry.key
            if (metCiv == civInfo || metCiv.isBarbarian
                || civInfo.diplomacy.containsKey(metCiv.civID)) continue
            civInfo.diplomacyFunctions.makeCivilizationsMeet(metCiv)   // ⑥ 初见建交
            // 双方各收一条 "We have encountered ..." 通知（略）
        }
        discoverNaturalWonders()                     // ⑦ 首见自然奇观
    }
}

脑内模型是巡逻队交班：换班时白板重写，随后班长逐项交代——谁在盯隐身、照片墙更新、新到的地方画进地图、今天碰见了谁。

① setNewViewableTiles 重写账本——四路来源见上一块。

② viewableInvisibleUnitsTiles：带 CanSeeInvisibleUnits unique 的单位（如驱逐舰反潜）额外看见的隐身单位所在格，海军战斗用它过滤“看得见潜艇吗”。

③ 对视野内每格 civInfo.setLastSeenImprovement(tile.position, tile.improvement)——把“现在看到的改良”存进文明的记忆表（AI 跳过，它们不看画面）。第 3 节展开。

                       explorerPosition: HexCoord? = null) {

        hasUnique(UniqueType.NoSight) -> hashSetOf(getTile())      // ① 零视野：只见脚下
        hasUnique(UniqueType.CanSeeOverObstacles) ->

                                                                   // ② 无视遮挡：几何圆
        else -> getTile().getViewableTilesList(getVisibilityRange()).toHashSet()
    }                                                              // ③ 正常：第 1 节算法

    val shouldUpdateTiles = updateCivViewableTiles
        && oldViewableTiles != viewableTiles                     // ④ 集合没变就免算
        && (oldViewableTiles.any { it !in civ.cache.ourTilesAndNeighboringTiles }
            || viewableTiles.any { it !in civ.cache.ourTilesAndNeighboringTiles })
                                                                   // ⑤ 全在自家领土内也免算

    if (!shouldUpdateTiles) return

    // TriggerUponDiscoveringTile 的触发（略）

    civ.cache.updateViewableTiles(explorerPosition)                // ⑥ 真要变：整本重算
}

Godot 对照：三态渲染映射到你的项目

Godot 4.x 的 TileMapLayer 天然适合“按层分类”：地形层、装饰层、单位层各一个，与 TileGroupMap 的十二层同构。三态迷雾的推荐做法：一张自定义的 per-tile 可见性枚举（unexplored / explored / visible）存在游戏数据里（对应 exploredBy 名单 + viewableTiles 账本），渲染层用一张覆盖全图的 CanvasLayer 或 shader 按枚举刷透明度；“explored 显示旧照片”则把 lastSeenImprovement 做成 Dictionary<Vector2i, String>，与 Unciv 的 LastSeenImprovement 同构。有两个 Unciv 值得抄的细节：一、新探索禁用 undo——任何“信息增益”都该禁；二、账本整表替换而非原地改——Godot 的信号系统下，替换后发一个全量刷新信号比监听每次增量简单可靠。

心智模型

  • 视线按环推进：每格记“来路上见过的最高地形”（maxHeightSeenToTile），下一格只跟一环内邻居中最低的那条垭口比——a≥b 不挡、c>b 翻得过；视野多算一环，界外只留高个。
  • 高度表：unitHeight 按层累加（平 0 丘 1 山 2），森林不加高度但 BlocksLineOfSightAtSameElevation 让 tileHeight=unitHeight+1——看得见（tileHeight）与打得着（unitHeight）是两个判定。
  • 文明账本 viewableTiles 是四路拼集（领土邻格、单位视野、盟友领土、间谍），整表替换防并发；单位移动只有在新旧视野集合不等且不全在自家领土时才触发重算。
  • 可见必已探索：viewableTiles 是文明持有的瞬时引用（@Transient 不进存档），exploredBy 是格子持有的持久名单（进存档）；新探索一格禁用 undo。
  • 雾里显示旧照片：人类玩家读 lastSeenImprovement（坐标→改良名的记忆表），AI/观战读真值；拍照只发生在“看得见”期间，走出视野后敌人拆农场不影响你的画面。
  • 画面两层组织：每格 TileGroup 十一层（地形在底城市按钮在顶），整图 TileGroupMap 按层归类成十二个全图层——点击走影子层命中格子；全图重刷靠各层“没变就早退”撑住性能。
