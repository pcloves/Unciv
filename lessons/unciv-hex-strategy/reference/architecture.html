常用术语

对局状态 / Game State
这局游戏当前的数据，包括回合数、文明、城市、地块和单位，由 GameInfo 统一持有。
规则集 / Ruleset
地形、建筑、单位、科技等规则定义；GameInfo.ruleset 用 @Transient 标记，不写入对局存档。内置定义在 android/assets/jsons/ 下，启动时由 RulesetCache 加载缓存，每局再按 gameParameters 组合出新的容器。
补全运行时数据 / setTransients
补上对局和规则对象的引用，重算缓存等数据；@Transient 只控制保存时忽略字段，不会自动完成这些工作。
文明 / Civilization
这局游戏里的一个玩家势力，管理自己的城市和各项事务；区别于规则集中定义的民族模板。
文明回合 / 全局轮次
文明的 startTurn、endTurn 分别处理回合开始和结束；文明索引回到首位时，整局计数 GameInfo.turns 才加一。
产出 / Yield
根据当前条件算出的食物、生产力、黄金等数值；算出的收益不代表已经加进库存。
存量 / Stock
已经积累的数量，例如 Civilization.gold 是国库余额，而不是每回合的黄金净收益。
基础地形 / baseTerrain
地块地形分层的最底层（Tile.baseTerrain，必有）：Grassland、Desert、Ocean 等；森林、丘陵等特征（terrainFeatures）叠在它上面，判断一格“是什么地”先看它。
玩家视角 / GameView
从指定文明的视角查询游戏状态；它负责提供数据，WorldScreen 负责显示界面。
序列化字段 / Serialized
写进存档的字段，只能是 ID、名字、坐标、数值等能文本化的数据；对象引用要另存 ID 或名字，读档后重建。
运行时引用 / Transient 引用
标 @Transient 的字段，不写进存档；由 setTransients 按保存的 ID、名字、坐标重新补上，例如 City.civ、Tile.owningCity。
规则 / Unique
一条可查询的效果或条件，在 JSON 里是带占位符的字符串，例如 [+1 Food] from [Deer] tiles [in this city]。第一次访问时解析成 Unique 对象。
占位文本 / placeholderText
把一条规则的参数都压成 [] 后剩下的模板；用它查 UniqueType.uniqueTypeMap 得到规则类型，例如 [stats] from [tileFilter] tiles [cityFilter] 命中 StatsFromTiles。
判定场景 / GameContext
查询规则时携带的上下文（城市、地块、文明等对象）；<when ...> 条件修饰语靠它判定是否满足。
组合规则集 / combined Ruleset
每局游戏由 RulesetCache.getComplexRuleset 组合出的新 Ruleset 容器；Map 是新的，但定义对象与缓存共享同一批实例。
测试对局 / TestGame
测试专用的一局最小游戏工厂，克隆 G&K 规则集并造单格地图，用 addCiv、addCity、createBuilding 等助手在内存里摆局面，不启动游戏窗口。
三段式 / given-when-then
测试的典型结构：given 摆输入，when 调方法，then 用断言核对结果；Unciv 测试里写成注释。
断言 / assert
JUnit 检查语句，例如 assertEquals(4, civ.gold)；实际与预期不符就让测试失败，是回归保护。
关键断点 / key breakpoint
断言失败时最先怀疑的那一行生产代码；读测试要把预期值和产生它的代码对上。

对象职责

问题源码入口注意区别
这一局的数据在哪里？GameInfo → civilizations / tileMapUncivGame 管理应用和界面
城市怎样找到自己的地块？City 的 location / workedTiles；TileMap 的地块城市记录坐标，地块数据在地图中
从谁的视角查询数据？GameView 及各类 View这些对象包装已有状态，没有复制一局游戏
谁处理文明和城市的结算？TurnManager / CityTurnManagerGameInfo 决定文明的处理顺序
谁显示结算后的局面？startNewScreenJob → UncivGame.loadGame这里的 loadGame 接收已有状态，不用再读存档

状态树与三类数据

GameInfo（存档的根）
  civilizations → Civilization → cities → City（location、tiles 都是坐标）
  tileMap → TileMap → tileList → Tile（地块全图只存一份）
  gameParameters → 开局设置，规则集的名字也在这里
  (transient) ruleset → 规则定义，按 gameParameters 取

跨对象的引用在存档里写成 ID、名字、坐标，读档后由 setTransients 重建：City.centerTile = tileMap[location]；单位的 currentTile 由所在 Tile 补上；Tile.owningCity 沿 getOwner() → getCity() → civ 找到文明。

类别例子保存方式
对局状态turns、City.location、Tile.baseTerrain、Civilization.gold写进存档，只存 ID、坐标、数值
规则定义Ruleset：地形、建筑、单位模板不写进存档，按 gameParameters 取
运行时引用与缓存civ、centerTile、owningCity、tileMatrix、viewableTiles@Transient，setTransients 重建

判断一个字段：它写进存档吗？改它要不要同步别处？读档后谁负责补上？状态存在不等于视角可见——界面通过 GameView 按 viewer 过滤数据。

规则集与 Unique

一条规则怎样进入游戏：
Buildings.json 的 uniques 字符串
  → Ruleset.load → buildings["Granary"]（定义对象，全局共享）
  → RulesetCache（内置规则集缓存，进程内一份）
  → getComplexRuleset → 本局 ruleset（新容器，定义对象共享）
  → CityConstructions.updateUniques → builtBuildingUniqueMap（属于这一城）
  → 使用点查询：city.forEachMatchingUnique(type, gameContext)
      → 条件修饰语 <when ...> 不满足则跳过；倍率按 <for every ...> 展开
      → 使用点读 unique.params，套到当前对象上

规则自己不运行，效果在查询时得出。定义对象约定只读，改规则靠模组覆盖同名对象。unique 是字符串，第一次访问才惰性解析：placeholderText 压参数查 uniqueTypeMap 得类型，params 供使用点取数。查询分三层来源：全局规则（getGlobalUniques()）、文明规则、城市本地规则（已建建筑与宗教）。

入口回答的问题关键点
RulesetCache启动时加载哪些规则集，每局组合哪份loadRulesets 只在启动跑；getComplexRuleset 每局新容器
Ruleset.load / addJSON 怎样进字段，模组怎样覆盖RulesetFile 枚举声明文件名；putAll 同名覆盖
Unique字符串怎样变成带类型和参数的对象placeholderText / params / type / modifiers
UniqueType这条模板属于哪种规则uniqueTypeMap 按占位文本查枚举项
builtBuildingUniqueMap规则何时进入这一城建成时 updateUniques 收集，并立即重算产出

测试与证据

一条测试怎样当证据：
tests/src/com/unciv/...（与主源码同包结构）
  @RunWith(BaseTestRunner::class)   ← 多数测试，调用线程直跑，不碰界面
  TestGame()                        ← 克隆规则集 + 单格地图 + 内存文明/城市
    given（输入）→ when（执行）→ then（断言）
    断言失败 → 回生产代码找产生预期值的那一行（关键断点）
读档测试：
  LoadGameTest 存真实历史存档串 → UncivFiles.gameInfoFromString
    → json().fromJson(GameInfo) → setTransients() → 旧档仍能还原

单元测试的工作目录指向 android/assets（见 tests/build.gradle.kts 的 workingDir），所以能读到真实 JSON。逻辑与界面分开：需要 GL 上下文的测试才换 GdxTestRunner（mock GL20 + HeadlessApplication）。读测试先问四个问题：输入、预期、关键断点、以及断言锁的是“确定值”还是“关系”。

入口回答的问题关键点
TestGame测试怎么造一局不启动游戏的对局clone 规则集可改；addCiv/addCity/createBuilding 摆局面
BaseTestRunner普通测试在哪跑、跑得为何快调用线程直跑，支持 Gdx.files，不碰 Gdx.app/input/graphics
CityTest城市销毁、卖建筑等行为的可见后果given/when/then 注释；断言钉住确定值
LoadGameTest旧存档今天还能不能读回真实存档串当输入；@Ignore 是更新存档的工具
UncivFiles.gameInfoFromString存档字符串怎样变成 GameInfo解压 → 反序列化 → setTransients 补引用

回合调用链

NextTurnButton.onActivation
  → 当前 NextTurnAction.action
  → NextTurn 分支：confirmedNextTurn → WorldScreen.nextTurn
      → 后台：clone → setTransients → GameInfo.nextTurn
          → 当前人类文明 endTurn
          → AI 文明逐个 startTurn → automateTurn → endTurn
          → 下个人类文明 startTurn
      → startNewScreenJob → UncivGame.loadGame
          → GL 上下文：创建并切换 WorldScreen
          → 满足间隔条件时请求自动存档

上面只列出了正常进入下一回合的流程。选科技、选生产，以及模拟、观战、战败、联机等情况，还需查看对应分支。点击一次按钮，不一定让整局回合数加一。

文明内部：更新产出汇总 → 黄金等入账 → 逐个调用城市 endTurn → 单位和外交等后续处理。城市在 endTurn 中累积生产力、处理人口，在 startTurn 中检查能否完成建造。详细顺序和条件见原方法。
