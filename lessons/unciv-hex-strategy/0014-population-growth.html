第三阶段 / 经济专题 · 人口专题

人口怎样工作和增长

第 13 课已经把每块地的产出算成结算单。这一课追问下一步：哪些地块真的把粮食送进城市？城市扣掉人口消耗后还剩多少？存粮怎样在回合结束时变成人口？答案分在三个对象里：City 保存领土与人口工作的地块，CityStats 算当前净粮食，CityPopulationManager 管存粮、增长和自动安排人口。

需要的基础：第 13 课的地块结算单、statsFromTiles 与 currentCityStats；第 06 课的地块状态；第 04 课的测试证据方法。源码版本：1df6249a41301056ddc4448a95a93ddf5403e061。

目标、回顾与场景

本课的三个问题

  • 谁在工作：城市拥有的地、可以工作的地、人口实际工作的地分别由什么表示？
  • 剩多少粮：City.foodForNextTurn() 为什么不是简单地把所有地块粮食相加？
  • 何时增长：存粮达到多少才长人口，增长后又怎样给新人口安排工作？

读完要能手算下面这个人口 1 的小城市：两块实际进账的地给 5 粮，人口吃掉 2 粮，本回合净增 3 粮；存粮从 12 到 15 时长到人口 2。

口述回顾：第 13 课

  2. 城中心为什么可以不分配人口就进账？
  3. statsFromTiles 和 currentCityStats 分别处在结算链的哪一层？

本课会把“有一块地的产出”接到“人口能否工作”和“城市粮食结余”上。

1. 所有权和人口分配不是一回事

先把三种“地”分开。城市扩张时，地块被城市拿到手；人口分配时，城市从自己的候选地里挑几块工作；城市统计时，只有符合条件的地块才进入收入。三个动作经常连续发生，所以很容易在脑中合成一个“城市有地就有产出”的错误规则。

// City.kt。问：这三个集合分别回答什么问题？
var tiles = HashSet<HexCoord>()                 // ① 城市保存的领土坐标
var workedTiles = HashSet<HexCoord>()           // ② 人口实际工作的坐标
var lockedTiles = HashSet<HexCoord>()           // ③ 自动分配时不挪走的地块

fun getWorkableTiles() = tilesInRange.asSequence()
    .filter { it.getOwner() == civ }             // ④ 领土 + 工作范围的候选
fun getWorkedTiles(): Sequence<Tile> =
    workedTiles.asSequence().map { tileMap[it] } // ⑤ 坐标查回 Tile
fun isWorked(tile: Tile) = workedTiles.contains(tile.position) // ⑥ 是否有人在这里工作

脑内模型是领土、工作地点、锁定地点：tiles 是城市控制的地块，workedTiles 是今天确实有人工作的地块，lockedTiles 是自动重新分配时不能挪动的地块。

① tiles 保存的是坐标集合，表示城市控制哪些地块；它不等于这些地块今天都产出。

② workedTiles 也是坐标集合，但含义变成“人口实际在哪些地块工作”。普通地块只有进入这里，才有机会进入城市的地块收入。

③ 锁定只影响自动重新分配，不是第三种领土。它让玩家手动指定的工作不被自动安排随意改掉。

④ getWorkableTiles() 先从城市工作范围取地，再要求 getOwner() == civ。因此别的城市拥有的地，即使在几何范围内，也不是本城候选。

⑤⑥ 集合存坐标，查询时再通过 tileMap 找回实际 Tile；isWorked 只是检查这块地的坐标是否在集合里。

所有权由扩张管理器修改，人口工作的地块由 City.workTile 记录。它们是两条不同的状态变化路径：

fun workTile(tile: Tile): Boolean {
    require(getWorkableTiles().contains(tile))      // ④ 只能安排到本城可工作地
    if (isWorked(tile)) return false
    workedTiles = workedTiles.withItem(tile.position) // ⑤ 加入工作地块集合
    return true
}

2. 人口怎样找到工作

人口管理器先算出“还有几个人没有安排工作”，再为每个自由人口比较地块和专家。这里先只看地块；专家是另一条分配分支。

// CityPopulationManager。问：一个人口是否空闲？
fun getFreePopulation(): Int {
    val workingPopulation = city.getWorkedTiles().count() // ① 普通工作人口
    return population - workingPopulation -
        getNumberOfSpecialists()                        // ② 再扣专家
}

3. 粮食结余从哪里来

下面这个城市沿用第 13 课的结算单：城中心草地给 2 粮；草地上的农场有人工作，给 3 粮。城市先把符合条件的地块相加到 statsFromTiles，然后在最终城市统计中扣除人口消耗。foodForNextTurn() 读取的是这个最终净值。

// CityStats.updateTileStats。问：哪些地块能进入城市地块收入？
val workedTiles = city.tilesInRange.asSequence()
    .filter {
        city.location.toHexCoord() == it.position        // ① 城中心免费
        || city.isWorked(it)                             // ② 人口安排
        || it.owningCity == city && (...                // ③ 免人口产出格
            it.getUnpillagedTileImprovement()
                ?.hasUnique(TileProvidesYieldWithoutPopulation, ...)
            || it.terrainHasUnique(TileProvidesYieldWithoutPopulation, ...))
    }
for (tile in workedTiles) {
    val tileStats = tile.stats.getTileStats(city, city.civ) // ④ 取第13课结算单
    stats.add(tileStats)                                  // ⑤ 累加
}
statsFromTiles = stats                                    // ⑥ 钉住地块收入

4. 存粮怎样换成人口

粮食有两个位置：foodForNextTurn() 是每回合流量，foodStored 是粮仓存量。回合结束时，CityTurnManager 把前者交给人口管理器；人口管理器再决定粮仓是否达到下一人口阈值。

// CityPopulationManager。问：人口 1 需要多少粮？
fun getFoodToNextPopulation(): Int {
    var foodRequired = 15 + 8 * (population - 1) +
        floor((population - 1).toDouble().pow(1.5))    // ① Civ V 基础曲线
    foodRequired *= city.civ.gameInfo.speed.modifier       // ② 游戏速度
    if (city.civ.isCityState) foodRequired *= 1.5f        // ③ 城邦
    if (!city.civ.isHuman())
        foodRequired *= city.civ.gameInfo.getDifficulty()
            .aiCityGrowthModifier                            // ④ AI 难度
    return foodRequired.toInt()
}

① 基础曲线从人口数计算需求。人口 1 代入后是 15 + 0 + floor(0)，所以本案例需求为 15。

② 速度会整体调整需求，因此“人口 1 永远需要 15”不准确；15 是标准速度下的本案例数值。

③ 城邦额外乘 1.5；④ AI 还受难度修正。这些条件说明源码把平衡参数集中在同一个入口，而不是散在回合逻辑里。

本课手算先固定为标准速度、普通人类城市，避免把可选修正混进主模型。

fun nextTurn(food: Int) {
    foodStored += food                                     // ② 流量进入粮仓
    if (foodStored < 0) {                                  // ③ 饥荒
        if (population > 1) addPopulation(-1)
        foodStored = 0
    }
    val foodNeededToGrow = getFoodToNextPopulation()       // ④ 读取阈值
    if (foodStored < foodNeededToGrow) return               // ⑤ 还没长
    if (city.avoidGrowth) { foodStored = foodNeededToGrow; return } // ⑥ 封顶
    foodStored -= foodNeededToGrow                         // ⑦ 扣掉成本
    addPopulation(1)                                       // ⑧ 人口增长
}

5. 增长后为什么要重新分配人口

人口增加不是只改一个整数。新人口必须找到工作，否则它是自由人口；同时城市统计需要重新计算，因为人口消耗变了，人口来源的生产力也变了。Unciv 把“增长完成”和“重新人口安排”连接起来，但没有把两者写成同一个循环。

// CityPopulationManager.addPopulation 与 nextTurn 的增长尾部。
addPopulation(1)
city.shouldReassignPopulation = true                        // ① 标记需要重新分配人口

fun addPopulation(count: Int) {
    val changedAmount = count.coerceAtLeast(1 - population)
    population += changedAmount                                 // ② 先改人数
    val freePopulation = getFreePopulation()
    if (freePopulation < 0) {
        unassignExtraPopulation()                              // ③ 人不够岗位时收回
        city.cityStats.update()
    } else {
        autoAssignPopulation()                                  // ④ 有空闲人口就找工作
    }
}

与第 13 课的连接：人口新增后，statsFromTiles 可能因为多了一块人口工作的地块而增加；但人口自己的基础生产力来自 CityStats.updateBaseStatList 的 “Population” 行，不要把它重复塞进地块收入。

心智模型

  • 所有权是“这块地归谁”，人口安排是“今天谁在这块地工作”。Tile.owningCity 和 City.workedTiles 是两种不同状态。
  • 人口不是地块列表。population 只记录人数；普通人口安排坐标和专家分配分别保存在 workedTiles 与 specialistAllocations。
  • 城市粮食结余是最终净值。地块收入先进入 statsFromTiles，城市统计再扣人口消耗，foodForNextTurn() 读取 currentCityStats.food。
  • 存粮和流量要分开。foodStored 是粮仓里已有多少，foodForNextTurn() 是本回合结算后增加或减少多少。
  • 增长是一个回合边界动作。回合结束把净粮食加入存粮；达到阈值后扣阈值、增加人口，并触发后续重新分配人口与统计更新。

选择题答案与核对位置

1：人口正在这块地工作；2：扣除人口消耗后的粮食；3：存粮达到增长阈值；4：所有权记地块归谁，分配记谁在哪些地块工作。分别对应 所有权与人口分配、最终净粮食、增长阈值、两个集合的区别。

练习 A · 手算一个小城市（10 分钟）

标准速度、普通人类城市、人口 1。城中心草地给 2 粮；一块归本城所有、且有人工作的草地农场给 3 粮；没有其它粮食修正。① statsFromTiles.food 是多少？② 人口消耗多少？③ foodForNextTurn() 是多少？④ 粮仓已有 12 时，本回合后会不会增长？

展开核对要点

① 是 5 粮：城中心 2 + 有人工作的农场 3。② 人口 1 默认消耗 2 粮。③ 最终净粮食为 5 − 2 = 3，foodForNextTurn() 返回 3。④ 会增长：12 + 3 = 15，达到人口 1 的标准速度阈值；扣除 15 后存粮为 0，人口变成 2。

练习 B · 所有但没工作（8 分钟）

城市已经通过 takeOwnership 拿到一块草地农场，但人口仍在城中心，workedTiles 不包含这块农场。① 这块地属于谁？② 它是否是 getWorkableTiles() 的候选？③ 它会不会进入普通的 statsFromTiles？④ 如果调用 workTile 后呢？

展开核对要点

① Tile.owningCity 指向本城，城市的 tiles 也包含其坐标。② 若仍在工作范围内且没有其它所有者，它是候选。③ 不会，普通地块还要满足 city.isWorked(it)；只有城中心或免人口产出格可以例外进账。④ workTile 把坐标加入 workedTiles，下一次 updateTileStats 才把农场结算单加进城市。

练习 C · 增长后的人口去哪（6 分钟）

人口 1 的城市本回合达到增长阈值，调用 addPopulation(1) 后，为什么不能只把 population 加一就结束？请按源码说出至少两个后续动作。

展开核对要点

人口增加会先改变人口消耗和 Population 来源的统计；然后 getFreePopulation 可能变为正，autoAssignPopulation 会比较地块和专家并调用 workTile 或分配专家；增长还设置 shouldReassignPopulation，让回合开始时按焦点重新排班；最后城市统计需要更新。

练习 D · 本地核验（可选，10 分钟）

运行既有 CityPopulationManagerTest：① 哪个测试证明 14 存粮加 1 粮会增长？② 哪个测试证明增长后会自动安排人口？③ 哪个测试证明多出的粮食会结转？再回到 CityPopulationManager.nextTurn 找对应分支。

展开核对要点

① should increase pop when enough food is stored 设置 14 并调用 nextTurn(1)，断言人口为 2、存粮为 0。② should automatically assign new pop to job 同样增长，并断言自由人口为 0。③ should carry over excess food when new pop is born 设置 14、加入 4，增长后断言存粮为 3；对应源码是先扣 15，再留下超出的 3。
