陆海与气候分布

第七课看到了地图生成的整条流水线，这一课钻进前两道工序：MapLandmassGenerator 怎样用一块柏林噪声决定哪格是海，applyHumidityAndTemperature 又怎样用纬度加噪声算出每格的温度湿度，再交给规则集里的“温度湿度区间表”定下草原、荒漠还是冻土。读完你应当能从参数和中间结果解释连续分布为什么形成地形，并预测调整参数的影响。

需要的基础：第七课的阶段链、随机源归属与环绕噪声入口。源码版本：1df6249a41301056ddc4448a95a93ddf5403e061。

目标、回顾与场景

先给三个场景，三个都是新游戏界面上真实存在的选项。场景一：把“地图类型”下拉框换成 Archipelago（群岛），生成出来的图碎成一片小岛——每种类型背后是一个 createXxx 函数（第 4 节的表全部列出）。场景二：高级设置里把 Water level 滑块拉高，同一颗种子的大陆明显缩小。场景三：把 Temperature shift 拉到正数，冻土和雪原退到地图边缘，荒漠挤到中间。这三个旋钮背后是同一套机制：一块连续的噪声场加上一个阈值，再叠一层纬度决定的温度。

本课的三个问题

  • 噪声到陆海：每格的 elevation 从哪来？为什么相邻格子倾向同为陆地或海洋？
  • 参数到分布：waterThreshold、scale、倍频参数各自改变分布的什么？
  • 气候到地形：temperature 和 humidity 怎样算出来，又怎样落成具体地形？

读完还要会一件事：不看正文，对一个“调参后的地图会变成什么样”的预测，说出证据在源码的哪一行。

口述第七课的三个结论

  1. generateMap 的阶段链顺序你还能排出来吗？陆海和温湿各排第几？
  2. 噪声的 seed 参数与地图 seed 是什么关系？（提示：切 z 层）
  3. 环绕地图的噪声为什么要卷成圆柱？

这三条是第七课的骨架，本课直接在它们之上展开。答不上来的先回 第七课第 2、4 节扫一眼。

1. 陆海分布：一块噪声切一刀

第七课的阶段链里，MapLandmassGenerator 是第一道工序。它先从规则集里找出“初始陆地”和“初始水体”两种地形的 名字，然后按地图类型算出每格的 elevation（海拔），最后用一条阈值线切开：

// MapLandmassGenerator.kt 的两个字段与核心判定；①～③ 与右侧对应。
class MapLandmassGenerator(
    private val tileMap: TileMap,
    ruleset: Ruleset,
    private val randomness: MapGenerationRandomness
) {
    // ① 只拿两种地形的名字：初始陆地 / 初始水体
    private val landTerrainName = getInitializationTerrain(ruleset, TerrainType.Land)
    private val waterTerrainName: String = try {
        getInitializationTerrain(ruleset, TerrainType.Water)
    } catch (_: Exception) {
        landTerrainName   // 纯陆地模组：水体名退化为陆地
    }
    private val landOnlyMod: Boolean = waterTerrainName == landTerrainName

    // ② 水位线：generateLand 开头会被界面参数覆盖
    private var waterThreshold = 0.0

    // ③ 全类共用的落笔点：低于阈值写水体名，否则写陆地名
    private fun spawnLandOrWater(tile: Tile, elevation: Double) {
        tile.baseTerrain =
            if (elevation < waterThreshold) waterTerrainName
            else landTerrainName
    }
}

① 构造时只拿两个名字，不拿地形对象——baseTerrain 是字符串字段（第六课），比对和后续 setTerrainTransients 都够用。纯陆地模组找不到水体地形时，waterTerrainName 直接退化为陆地名字，后面整段生成可以跳过。

② waterThreshold 初始为 0.0，generateLand 开头会被 mapParameters.waterThreshold 覆盖（新游戏高级设置里的 Water level 滑块，范围 −0.1～0.1）。

③ spawnLandOrWater 是全类共用的落笔点：elevation 低于 waterThreshold 就写水体名，否则写陆地名。所有地图类型的差别只在“elevation 怎么算”，落笔只有这一行。

最直白的类型是 Perlin：每格算一次噪声，切一刀完事。注意下面这个函数名的来历——generateLand 里有一张 when (tileMap.mapParameters.type)，玩家在新游戏界面选了哪个地图类型（MapType），就分派到对应的 createXxx 私有函数：选 Pangaea 走 createPangaea，选 Archipelago 走 createArchipelago……一共 13 个，全部列在第 4 节的表里：

// MapLandmassGenerator.createPerlin：整图类型里最简单的一种。
private fun createPerlin() {
    // ① 抽本阶段的 z 层（噪声种子）
    val elevationSeed = randomness.RNG.nextInt().toDouble()
    for (tile in tileMap.values) {
        // ② 每格只读噪声场，不再动 RNG
        val elevation = randomness.getPerlinNoise(tile, elevationSeed)
        spawnLandOrWater(tile, elevation)
    }
}

① 第七课说过：先从 RNG 抽一个整数当本阶段的 z 层（噪声种子）。

② 循环里每格调 getPerlinNoise 拿一个大约在 −0.55～0.55 之间的值当 elevation，不再动 RNG——同一张图内每格的随机性全部来自噪声场本身。这就是“连续分布”的第一层含义：相邻格的噪声值天然接近，所以相邻格倾向落在阈值线的同一边。

但一刀切下去未必有好结果——比如水太多。部分类型外面套了一层重试：

// MapLandmassGenerator.retryLoweringWaterLevel（部分代码）：
// 水太多就调低水位线重来，最多 30 次；①～③ 与右侧对应。
private fun retryLoweringWaterLevel(
    predicate: (waterPercent: Float) -> Boolean = { it <= 0.7f },
    function: () -> Unit
) {
    var retries = 0
    while (++retries <= 30) {
        // ① 重新生成整张陆海，统计水占比
        function()
        val waterPercent = tileMap.values
            .count { it.baseTerrain == waterTerrainName }
            .toFloat() / tileMap.values.size
        // ② 两处出口：水占比达标，或阈值已低于 -1
        if (waterThreshold < -1f || predicate(waterPercent)) break

        // ③ 降低水位线：基础步长 × 水占比 × 重试次数的平方根（加速）
        waterThreshold -= 0.02 *
            (waterPercent / 0.7f).coerceAtLeast(1f) *
            retries.toFloat().pow(0.5f)
    }
}

① 每轮先跑一遍 function（重新生成整张陆海），再统计水占比。默认接受条件是水不超过 70%。

② 两处出口：水占比达标，或阈值已经低到 −1 以下（几乎全陆地还做不到就放弃）。注意 function 每轮重新抽噪声种子（在类型函数的 lambda 里），所以每轮切的是一块新噪声。

③ 不满足就往下调阈值重新切：步长 = 0.02 ×（水占比/0.7，至少 1）× 重试次数平方根，后期步子越迈越大。阈值降低意味着“低于阈值才算水”的格子变少——水位线下降，陆地扩大。

第七课讲过环绕地图的噪声要卷成圆柱（getNoise 的环绕分支），本课不再重复入口，只补一句衔接：卷圆柱只是把每格的平面坐标换成圆柱面上的三维坐标再喂给噪声函数，噪声函数本身（下一节）完全不知道环绕的存在。

2. 柏林噪声：为什么连续

连续分布的技术根基是柏林噪声（Perlin noise）。Unciv 没有引库，直接搬了 Rosetta Code 的 Kotlin 实现（文件头注明 version 1.1.3）。它是一段大约 130 行的自包含代码：

// Perlin.kt（object Perlin，节选骨架）；①～④ 与右侧对应。
object Perlin {
    // ① 256 个数的固定置换表 + 梯度表 grad3 + 加长表 p
    private val permutation = intArrayOf(151, 160, 137, …)
    private val grad3 = arrayOf(
        intArrayOf(1,1,0), intArrayOf(-1,1,0), …)

    // ② 单倍频：一次 3D 柏林噪声，范围约 (-1, 1)
    fun noise(x: Double, y: Double, z: Double): Double

    // ③ 多倍频叠加，见第 3 节
    fun noise3d(x: Double, y: Double, z: Double,
                nOctaves: Int = 3, …): Double
    fun ridgedNoise3d(…): Double

    // ④ 三个私有辅助函数，本节后半逐一展开
    private fun fade(t: Double) = t*t*t*(t*(t*6-15)+10)
    private fun lerp(t: Double, a: Double, b: Double) =
        a + t * (b - a)
    private fun grad3(hash: Int, x: Double, y: Double, z: Double): Double
}

① 两个数据部件：permutation 是 0～255 的一个固定打乱顺序（写死在源码里，所有 Unciv 安装都一样）；grad3 是 12 个方向向量。它们只用于给格子角做哈希。

② noise 对一个三维点返回一个近似连续的值，是后面一切的地基。

③ 外面两个函数是倍频包装：noise3d 把多个频率叠起来，ridgedNoise3d 变体专造山脊状条纹。它们的差别第 3 节展开。

④ 三个私有函数是单倍频算法的零件，下面两段逐一展开。“写死的置换表”意味着噪声场对所有玩家相同——两张图不同，靠的是种子选了噪声空间的哪个区域（z 层和 offset），而不是换一张噪声场。

单倍频 noise 的算法分四步。这段先看骨架与预处理，③④ 的插值细节在下一段展开：

    val yi = floor(y).toInt() and 255
    val zi = floor(z).toInt() and 255

    val yy = y - floor(y)
    val zz = z - floor(z)

    val u = fade(xx)
    val v = fade(yy)
    val w = fade(zz)
    // ④ 八个角做哈希与三线性插值（见下）
    …

③ 的 fade 和 ④ 的插值是理解“为什么连续”的关键：

// Perlin.kt 的三个私有函数；①～③ 与右侧对应：
// ① 平滑曲线：两端导数为 0，压平格子边缘
private fun fade(t: Double) = t*t*t*(t*(t*6-15)+10)

// ② 普通线性插值
private fun lerp(t: Double, a: Double, b: Double) =
    a + t * (b - a)

// ③ 角点哈希选方向向量，与“点到该角的偏移”做点积
private fun grad3(hash: Int, x: Double, y: Double, z: Double): Double {
    val h = hash and 15
    return x * grad3[h][0] +
           y * grad3[h][1] +
           z * grad3[h][2]
}

// ④ 先哈希出 8 个角，再做三层 lerp 的三线性插值。

val aa = p[a] + zi
val ab = p[a + 1] + zi
val b  = p[xi + 1] + yi
val ba = p[b] + zi
val bb = p[b + 1] + zi

return lerp(w,

① fade 是一条特殊曲线：t=0 和 t=1 时值恰好是 0 和 1，且两端的一阶、二阶导数都是 0。它把小数位置“压平”到边缘，避免插值在格子边界处出现折角。

② lerp 是普通线性插值。

③ grad3 按角点的哈希选一个固定方向向量，再和“点到该角的偏移”做点积——8 个角各得一个基准值。

④ 三层嵌套的 lerp 把 8 个角的基准值按 fade 后的位置加权混合成一个数。连续性就在这里：点在格子内滑动时，xx/yy/zz 连续变化，fade 和 lerp 都是连续函数，输出自然连续。跨过格子边界也不跳变——同一条边界两侧的两个格子，fade 压到 0 和 1，插值恰好落在边界角的同一个基准值上。

Godot 对照：噪声开箱即用

Unciv 手写 Perlin 是因为 core 模块不依赖引擎。Godot 里 FastNoiseLite 内置 Perlin / Simplex / Cellular 等类型，frequency、octaves、lacunarity、persistence 参数一一对应本课的概念，还带无缝 tileable 选项（等价于 Unciv 的卷圆柱思路，Godot 在 2D 平面上做周期化）。写自己的生成器时，先在编辑器里调 FastNoiseLite 参数预览纹理，找到满意的形态再搬数值——比读代码猜分布快得多。Godot 4.x 均适用。

3. 倍频叠加与参数

单倍频噪声只有格子尺度的起伏。真实地形要“大轮廓 + 小细节”，noise3d 用倍频叠加实现：

// Perlin.noise3d：多个倍频（octave）加权求和。
fun noise3d(x: Double, y: Double, z: Double,
            nOctaves: Int = 3,
            persistence: Double = 0.5,
            lacunarity: Double = 2.0,
            scale: Double = 10.0): Double {
    var freq = 1.0
    var amp = 1.0
    var max = 0.0
    var total = 0.0
    repeat(nOctaves) {
        // ① 每个倍频：坐标乘 freq/scale 再采样
        total += amp * noise(x * freq / scale,
                             y * freq / scale,
                             z * freq / scale)
        max += amp
        // ② 频率翻倍、振幅减半
        freq *= lacunarity
        amp *= persistence
    }
    // ③ 除以振幅总和归一化
    return total / max
}

// MapGenerationRandomness.getPerlinNoise 的默认参数：
// ④ nOctaves=6, persistence=0.5, lacunarity=2.0, scale=30.0

本地 Perlin.ktnoise3d · L40getPerlinNoise · L33

① 每一轮（一个“倍频”）把坐标乘上 freq/scale 再采一次样。freq 越高，单位距离跨过越多格子，噪声变化越快——这就是“频率”。

② 每轮结束后 freq 乘 lacunarity（默认 2，频率翻倍）、amp 乘 persistence（默认 0.5，振幅减半）。

③ 最后除以 max（振幅总和）归一化，输出仍在 −1～1 附近。直觉：第 1 个倍频画大轮廓，第 2 个在轮廓上加一半幅度的中起伏，第 3 个再加四分之一幅度的小颗粒……频率越来越高、贡献越来越小。

④ 实际调用走 getPerlinNoise 的默认参数：6 个倍频、scale 30，所以陆地有大块连贯区域，边缘又不太光滑。

① 骨架与 noise3d 完全相同：逐倍频采样、逐轮调 freq/amp、最后归一化。

② 普通噪声在 0 附近穿过时变号；取 abs 后，穿过 0 的位置变成尖峰——原噪声的等高线变成了“山脊线”。叠加多个倍频后，脊线纵横交错，像群岛或山脉的走向。

调用点：Archipelago、Lakes、SmallContinents 用 ridged（要碎、要脊），大陆类和 Perlin 用普通 noise3d。给哪些类型用哪种噪声，第 4 节的表里列全。

四个参数对分布形态的影响方向，整理成一张表。这是本课“预测调整的影响”的核心：

参数控制什么调大后调小后
scale坐标除以的基数（观察距离）特征变大：整块大陆或大洋特征变小：斑点状碎岛
nOctaves叠加几层细节边缘更破碎、更自然边缘更平滑、更圆润
persistence高频层的振幅衰减细节更明显更接近纯大轮廓
lacunarity相邻倍频的频率倍数各层频率差距拉大各层频率接近，层次感减弱
waterThreshold陆海判定线（界面滑块 ±0.1）海拔低于更高阈值 → 水变多陆地变多

最后一个问题是地图大小与 scale 的关系。scale 是“多少格走完一个起伏周期”，地图变大而 scale 不变，大图上就能塞下更多个周期——结果大陆数量翻倍、每块相对变小。源码里两种做法都有，先看一个代入计算的例子。

做法一：scale 跟着地图变大（Fractal 类型）。createFractal 先算 ratio = maxdim / 32，其中 maxdim 是地图的 maxLatitude 和 maxLongitude 里较大的一个（TileMap 的两个 lazy 属性，按实际地块取绝对值最大），再乘 30 当 scale。代入两种尺寸（第六课的 MapSize 预设，以下数字经 Kotlin REPL 用真实 TileMap 实测）：

Small（33×21）：maxdim = 21 → ratio ≈ 0.66 → scale ≈ 20 → 21 / 20 ≈ 1.1 个周期
Huge （87×57）：maxdim = 57 → ratio ≈ 1.78 → scale ≈ 53 → 57 / 53 ≈ 1.1 个周期

maxdim 放大了 2.7 倍，scale 也放大 2.7 倍，两者相除不变：不管什么尺寸的图，都只装得下约一个大起伏周期。Huge 图的大陆和 Small 图一样是“两三块”，只是每块的绝对格数更多。源码注释原话正是 “change scale depending on map size so that average number of continents stay the same”（按地图尺寸改 scale，让平均大陆数保持不变）。

做法二：scale 锁死，不随地图变（Boreal 类型的湖）。createBoreal 里有两层噪声：大轮廓层影响海岸线，scale = 3×√radius，随图变大（Small 图 radius 15 时约 12，Huge 图 radius 40 时约 19）；湖层用 ridged 噪声，scale 写死 5.0——不管哪种尺寸的图，湖永远是“五格尺度的洼地”，图越大湖越多、单个大小不变。源码注释给的动机是湖是河流的源头（第 9 课），湖的大小如果跟着地图缩放，大图的湖会连片成海、小图的湖会缩成一格，河流生成就没有稳定的发源地了。

两种做法的取舍：想要“分布的块数不随图变”（大陆数），让 scale 跟尺寸走；想要“单个特征的绝对大小不随图变”（湖、局部地物），把 scale 锁死。同一个类里两种策略并存，各管各的层。做自己的地图生成时，这是每个噪声层都要问一遍的问题。

waterThreshold 的滑块范围只有 −0.1～0.1，因为噪声输出集中在 0 附近（getPerlinNoise 注释：多数值在 ±0.55 内、约 28% 低于 −0.1），小幅度移动阈值就能显著改变水陆比。

4. 十三种地图类型的骨架

上一节说过，玩家在界面选的每个地图类型（MapType）都对应一个 createXxx 函数。这 13 个函数共享同一套骨架：抽种子 → 每格算 elevation → spawnLandOrWater 落笔。逐个讲会重复，先说清楚它们只在两件事上不同，再看表。

第一件：elevation 的来源。要么主要靠噪声（Perlin、Archipelago），要么噪声只当扰动、主体是一条确定性公式（Spiral 的螺旋线、Boreal 的纬度曲线），要么噪声再叠一层几何“提升/压低”来保证宏观形状（Pangaea 的中央大陆、FourCorners 的四角）。第二件：要不要重试——第 1 节的 retryLoweringWaterLevel 只套在对水占比或大陆数有硬要求的类型上。

取舍：为什么地形匹配放在规则集而不写死在代码里

把“什么温湿出什么地形”做成 jsons 里的 TileGenerationConditions unique，模组作者不改一行 Kotlin 就能重画气候带：加一种红树林地形、把荒漠推得更湿……匹配代码（TerrainOccursRange）只提供矩形判定这一种原语。代价是矩形只能近似真实生物群的弯曲边界，所以每个地形要写好几条 unique 手工拼形状——你在 Snow 的五条规则里看到的就是这种“用矩形拼曲线”的手艺。另外温湿匹配地形在 ifEmpty { terrains } 处有兜底，模组定义的矩形覆盖不全也不会生成失败，只是退化成随机。

心智模型

  • 陆海 = 噪声 + 阈值：每格一个 elevation，低于 waterThreshold 落水；所有地图类型只改 elevation 公式，不改这条判定线。
  • 柏林噪声靠“格子角哈希 + fade 平滑 + 三线性插值”保证连续：点连续移动，输出连续变化；置换表写死，靠种子选噪声空间的切面。
  • noise3d 叠多个倍频：频率逐层翻倍、振幅逐层减半，大轮廓加小细节；ridged 变体取绝对值，等高线变山脊。
  • scale 管特征大小、nOctaves 管边缘破碎度、persistence 管细节强度、waterThreshold 管水陆比——调参前先想改的是哪个量。
  • 温度 = 5/6 纬度折线 + 1/6 噪声，再过 intensity 幂曲线和 shift；湿度 = 纯单倍频噪声折到 0..1。
  • 地形匹配在规则集：每个地形一组“温湿矩形”unique，格子的 (temperature, humidity) 落进谁的矩形就变谁；全不匹配则整组随机兜底。

练习 A · 推演参数变化（6 分钟）

三张相同 seed、相同类型的图，分别只改一处：① Water level 从 0 拉到 +0.1；② Biome size 从 6 拉到 15；③ Temperature intensity 从 0.6 拉到 0.8。各自预测陆海或温湿分布的变化，并说出源码证据在哪一行。

展开核对要点

① waterThreshold 变大，更多格子满足 elevation < waterThreshold（spawnLandOrWater，MapLandmassGenerator L99），水变多、大陆缩小。② tilesPerBiomeArea 是温湿噪声的 scale（applyHumidityAndTemperature L518、L560/566），调大后温湿场特征变大，气候带更成片（草原整块、荒漠整块），地形碎斑减少。③ intensity 进入幂指数 1−intensity（L568），调大后 |t|^(0.4) 比 |t|^(0.2)… 注意方向：intensity 变大 → 指数变小 → 中间值更被推向两端，热带和寒带都扩张、温带收窄。

练习 B · 读一组温湿矩形（6 分钟）

打开 android/assets/jsons/Civ V - Vanilla/Terrains.json，找到 Grassland 和 Desert 的 “Occurs at temperature …” 规则。一格温度 0.85、湿度 0.1，会匹配到谁？一格温度 0.85、湿度 0.35 呢？如果两个都不匹配，代码走哪条路？

展开核对要点

温度 0.85、湿度 0.1：Desert 的 “between [0.1] and [0.8] … [0.2]” 等矩形不匹配（湿度不足），但 “between [-0.1] and [0.9] and humidity between [0] and [0.2]” 匹配 → Desert。温度 0.85、湿度 0.35：Grassland 的 “between [0.8] and [0.9] and humidity between [0.6]” 不匹配（湿度不足）；Desert 各矩形要么温度超界要么湿度超界——去查 Plains：“between [0.8] and [0.9] and humidity between [0.2] and [0.6]” 匹配 → Plains。若全不匹配，ifEmpty { terrains } 兜底整组随机（MapGenerator L594），保证每格有地形。

练习 C · 比较两种噪声的用途（5 分钟）

Archipelago 用 ridged 噪声而 Perlin 类型用普通噪声。结合 ridgedNoise3d 取绝对值的差别，解释为什么群岛图选 ridged：它切完阈值后陆地的典型形态有什么不同？

展开核对要点

普通噪声的值围绕 0 缓慢起伏，阈值切出的陆地是团块状（有内部、有海岸线）。ridged 取 abs 后，原噪声接近 0 的等值带变成尖峰脊线——阈值切出的陆地变成窄条与碎片，正像群岛的岛屿链。另外 Archipelago 先把 waterThreshold += 0.25（L249），抬高水位线再切，碎片更小。

练习 D · 本地核验（可选，5～10 分钟）

跑 :tests:test --tests "com.unciv.logic.map.MapGenerationTests"。terrainTileCountsReasonableForHexMaps 聚合 20 颗种子的 perlin 六边图后断言各地形数量（如 Ocean ≈ 4079、Grassland ≈ 2140）。对照本课内容想一想：这些数字钉住的分别是阶段链的哪几步？为什么测试注释说“即使用 seed 也不确定”、要靠 assertApproximately 的两倍容差？

展开核对要点

Ocean/Coast 钉住陆海（第 1 步）+ 湖岸（第 4 步）；Grassland/Plains/Desert/Tundra/Snow 钉住温湿选地形（第 2 步）；Hill 属第 3 步、Forest/Jungle 属第 5 步、Ice 属第 7 步，本课只需意识到计数跨阶段。不确定性的来源之一：选地形时匹配多个候选要 randomOrNull(RNG)（L594），RNG 序列还受前面各阶段抽种子次数影响——同样是“地形跟着 seed 走”，但统计上仍有波动，所以用宽容差防回归而不是精确断言。（本课程核对时 Gradle MCP 实测 4 过 0 失败。）
