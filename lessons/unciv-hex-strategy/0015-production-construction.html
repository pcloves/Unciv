第三阶段 / 经济专题 · 城市建造

生产力怎样完成建造

城市正在训练一个单位，成本是 40，已经投入 35，本回合还能投入 12。按下“下一回合”后，进度会达到 47，但单位并不会在本方回合结束的那一刻出现。本课沿着这 47 点进度，追到单位生成、多出的 7 点生产力，以及玩家何时能控制新单位。

源码基线：1df6249a41301056ddc4448a95a93ddf5403e061；核对日期：2026-09-24。本文讨论普通城市生产路径；购买、免费获得与加速建造在相应位置说明边界。中文注释为教学所加；摘录的省略和改写均单独标注。

目标、回顾与场景

读完要能做什么

  • 手算完成后的溢出与下一个项目的进度，并解释新单位为什么此时才出现。

下面一直使用一个教学场景：队列先训练单位 A，再建建筑 B。A 的实际成本为 40、已有进度 35；B 的实际成本为 60、已有进度 0；城市没有旧溢出。本回合最终生产力为 12.4f，结算时取整为 12。城中心已有一个友方军事单位，但附近有可放置 A 的地块。这里的成本与产出是为验证而设定的输入，不是某个原版单位的固定数值。

  2. 其他文明行动A 尚未生成；此时地图上没有这个新单位。
  3. 本方下回合开始检查成本、放置 A，成功后保留 7 点溢出。

1. 产出、进度和溢出分别存在哪里

城市不会只保存一个“还差几回合”。它保存建造队列和每种项目的已投入进度，再根据当前产出估算剩余回合。换一个项目到队首，会改变本次生产投向哪里，却不等于把原项目的进度转给它。

// CityConstructions.addProductionPoints：完整方法，调整折行。
fun addProductionPoints(productionToAdd: Int) {
    val constructionName = currentConstructionName() // ① 获取当前项目
    val construction = getConstruction(constructionName)
    if (construction is PerpetualConstruction) {
        productionOverflow += productionToAdd         // ② 直接加点时的特殊分支
        return
    }
    if (!inProgressConstructions.containsKey(constructionName))
        inProgressConstructions[constructionName] = 0 // ③ 新项目从零开始
    // ④ 保存新进度
    inProgressConstructions[constructionName] =
        inProgressConstructions[constructionName]!! + productionToAdd
}

4. 多出的生产力不会立刻完成下一个项目

“溢出”在这里就是完成一个项目后，多出的生产力中允许保留的部分。按刚才的代码，计算顺序如下。这里的“缓存生产力”特指 completeConstruction 成功返回之后，在上限计算那一行读取到的值。

候选溢出 = 原项目进度 − 本次检查得到的实际成本
溢出上限 = max(本次实际成本, roundToInt(此时缓存生产力))
保存的溢出 = min(候选溢出, 溢出上限)

下一次普通生产结算：
新项目进度 += roundToInt(本回合最终生产力) + 保存的溢出
保存的溢出 = 0

回到 A、B：A 的成本为 40，多出的 7 小于上限的最低值 40，因此全部保留。假定本方新回合结束时，城市给 B 的最终生产力是 9.5f，取整为 10，B 才会获得 10 + 7 = 17 点进度。

表中每行表示一个阶段结束后的状态。“A 进度为 0（已删除）”是 getWorkDone(A) 的读数；不表示把完成后的 A 留在队列里从零重建。

每一步都有单独保存的位置：47 点先属于 A 的进度；完成后保留的 7 点转为城市的溢出；再到下一次普通生产结算，7 点才加入当时的队首。即使溢出足以支付 B 的成本，这次完成检查也不会自动连续完成 B。

换队首、空闲和项目失效时，应该分别看哪里
  • 换队首：合法的未完成项目按名称保留进度。A 已投入 20，改为建 B 并投入 12 后，可以同时有 A=20、B=12。
  • 空闲或持续转化：endTurn 跳过普通累加，旧溢出暂时保留；不是每空闲一回合就把当回合生产力继续攒进溢出。生产力转科学或黄金由城市统计中的转化逻辑处理。
  • 项目失效：validateInProgressConstructions 有另外的处理，例如失去建造资格的世界奇观可以退还黄金，某些过时单位的进度可以转给可建造的升级版本。这与成功完成时的溢出封顶是不同分支。

5. 单位怎样出现，为什么此时才出现

成本足够后，completeConstruction 会按项目类型执行实际建造。建筑进入城市的已建成集合；单位则要成为地图上的一个实例。单位放置失败时，不能先把原进度删除。

// CityConstructions.completeConstruction 的部分代码。
fun completeConstruction(construction: INonPerpetualConstruction): Boolean {
    var unit: MapUnit? = null
    if (construction is Building)
        construction.construct(this)                // ① 建筑进入城市
    else if (construction is BaseUnit) {
        unit = construction.construct(this, null)
            ?: return false                         // ② 单位放置失败即返回
        // ……省略保存的晋升方案处理
    }
    if (construction.name in inProgressConstructions)
        inProgressConstructions.remove(construction.name) // ③ 成功才删除进度
    if (construction.name == currentConstructionName())
        removeCurrentConstruction()                 // ④ 移除完成的队首
    validateConstructionQueue()                     // ⑤ 检查后续队列
    // ……省略完成通知等处理
    return true                                     // ⑥ 向调用方报告成功
}

源码对生成时机的解释 · L34人类行动前开始回合 · L476

Godot tip：先决定单位何时成为游戏状态，再显示节点

如果自己的回合制游戏也希望新兵出现后，所属玩家先有机会下达命令，可以把逻辑单位的创建安排在本方行动阶段之前，随后由表现层显示对应节点。仅仅延迟节点显示并不能保护已经进入战斗判定的单位。即时制游戏则要另行决定训练完成后的可操作时机和出生位置；不要直接照搬 Unciv 的回合边界。本课只比较规则设计，不要求实现 Godot 工程。

心智模型

  • 每回合产出、项目进度和溢出是三个数。currentCityStats.production 提供本回合数值，Map 保存各项目进度，productionOverflow 保存尚未使用的结余。
  • 普通生产在结束时加进度，在本方下回合开始时检查完成。达到成本与单位已经出现在地图上，是两个不同状态。
  • 完成必须先成功，才能删除原进度并保存这次溢出。单位放置失败会保留进度，后续检查可以重试。
  • 溢出先封顶，再等下一次生产结算。上限取实际成本与完成后该行读到的城市生产力整数值中较大者；不会当场循环完成整个队列。
  • 新单位赶上本方这次行动。城市先生成单位，随后统一开始单位回合，避免玩家控制之前先经历敌方行动。
